推荐新契约

不要只在现有 `embodiment` / `speechTimeline` 上打补丁。建议明确新增一个统一脚本对象。

AlicizationEmbodimentScriptV1 { turnId: string decisionTraceId?: string | null rendererTarget: 'live2d' replyText: string state: { baseEmotion: AlicizationEmotion delivery: AlicizationPerformanceDelivery emphasis: 0 | 1 | 2 residentMode: 'dialogue' | 'quiet-companionship' | 'idle-recovering' } speechPlan: { segments: EmbodimentSpeechSegment[] interruptPolicy: 'hard-stop' | 'soft-settle' preRollMs: number settleMs: number } facePlan: { preUtteranceCue?: string | null speakingCues: EmbodimentFaceCue[] postUtteranceCue?: string | null } motionPlan: { idleBase: string actionBursts: EmbodimentActionCue[] attentionMode: string } lipsyncPlan: { mode: 'energy-only' | 'energy-phoneme-hybrid' visemeHints?: EmbodimentVisemeHint[] } }

关键测试面

  • 同一句 reply 在相同 resident state 下生成稳定脚本，不随机漂移。
  • emotion / action / facial cue 被 renderer capability clamp 后，脚本仍自洽。
  • TTS 实际时长偏离估计时，mouth / face / motion 能被 reconciler 修正。
  • 用户打断时，audio stop、mouth settle、face settle、motion reset 顺序正确。
  • quiet companionship 不会误触发 speaking posture。
  • 中文长句、短句、疑问句、感叹句的 segment plan 质量稳定。
  • 当 TTS 缺少 phoneme/viseme 时，系统可退化到能量驱动但不中断表演链。

外部项目该怎么借鉴

  • N.E.K.O. 借鉴它的多 provider、queue-based TTS、实时打断与音频重采样思路，但不照搬它的三服务器结构，因为你当前产品目标不是平台化优先。
  • Open-LLM-VTuber 借鉴它对 hands-free、voice interruption、模块化 ASR/TTS/LLM 插拔的重视；但你应该把“心智治理 + 具身导演”做得比它更强，而不是只做模块拼装。
  • 你自己的仓库 现有 `speechTimeline`、`digitalLifeEnvelope`、`residentPerformance`、`body-kernel` 已经构成非常好的起点，关键是抽象收口。

第一批开发任务

任务 1：定义统一脚本契约

在 `packages/stage-shared` 新增 `AlicizationEmbodimentScriptV1` 及测试，明确它与 `embodiment`、`speechTimeline`、`digitalLifeEnvelope` 的关系。先让契约落稳，再做执行器改造。

任务 2：抽出 Embodiment Director

从 `use-stage-embodiment-presence.ts` 抽离 planning 逻辑，让它不再直接决定 Live2D/VRM/TTS 派发，只生成脚本和执行请求。

任务 3：升级 Speech Planner

把 `speechTimeline` 从“表现线索”升级为“可执行说话计划”，补上 segment interrupt、pre-roll、settle、prosody metadata。

任务 4：Live2D 驱动拆层

把 face / lipsync / motion 拆成明确 driver，统一消费同一脚本，不再由多个 composable 间接共享状态。

任务 5：Playback Reconciler 与 Telemetry

补上真实播放数据回流，让“估计时长”和“实际时长”的偏差能被系统吸收，而不是长期累计成嘴型和动作错位。
