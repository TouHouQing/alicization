模块边界与重构落点

不是另起炉灶，而是把现有分散逻辑“收编”为一个清晰的具身导演层。

现有资产怎么处理

`Alicization Runtime / Governance`

保留

继续做心智权威。特别是 `runtime-governance.ts`、`digital-life-spine.ts`、`mind-surface-renderer.ts` 这一层，不要下沉到 renderer 执行细节。

`presence dispatcher`

拆分

保留它作为“事件入口/去重/降级日志”，但把“performance planning”和“并行派发决策”抽出去。它不该继续承担导演职责。

`use-stage-embodiment-presence`

拆分

这里已经有 performance planning、variation token、resident merge 的雏形。应抽成独立 `Embodiment Director`，别继续埋在 renderer composable 里。

`use-stage-embodiment-speech`

拆分

保留为执行器，但把里面“timeline 对齐规则、fallback emotion/action cue 推断、synthetic speech 状态机”的权威判断尽量前移到 director / speech planner。

`pipelines-audio`

保留并增强

它适合继续做语音 segment/TTS/playback 的底层通道，但要升级 metadata 契约，让 segment 能带更多 viseme / prosody / interrupt 信息。

`Embodiment Director`

新增核心

新增独立模块，输入 `mind-turn-v1 + resident state + renderer capabilities`，输出统一 `performance script`。这是未来几年最重要的新边界。

推荐的新调用链

↓

为下一回合持续塑形

Director 至少要拆成 4 个子模块

  • Performance Script Builder：把 emotion / delivery / emphasis / facial cue / action cue 统一成单一脚本。
  • Speech Planner：决定分段、呼吸点、延迟预算、打断点、continuity hold、segment 优先级。
  • Renderer Capability Adapter：根据 Live2D 当前模型能力裁剪 cue，别把 renderer 兜底当成常态。
  • Playback Reconciler：根据真实音频时长、失败和打断，回流修正 timeline 与 resident state。

第一阶段不该做什么

  • 不要一开始做 Live2D / VRM 同权双栈导演。
  • 不要急着把所有 TTS provider 都做成高保真情感音色。
  • 不要把实时 VAD/ASR 先拉进一期主路径。
  • 不要继续把“动作计划”散落在多个 composable 内部维护。
