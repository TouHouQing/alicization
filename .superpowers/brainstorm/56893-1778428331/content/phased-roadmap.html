12-18 个月阶段路线图

顺序原则：先把“像活着的桌宠”做稳，再逐步拉高实时性、动作细腻度和本地化比例。不要一开始追满配。

P0 演出权威收口

0-2 个月

目标不是新增很多功能，而是让现有聊天闭环从“能跑”变成“同一时序下稳定演出”。

必须完成

  • 抽出独立 `Embodiment Director`。
  • 定义统一 `performance script` / `speech segment metadata` 契约。
  • 把 Live2D 作为唯一主渲染目标打磨通。
  • 为 TTS、口型、表情、动作建立统一 interrupt / cancel / settle 协议。
  • 记录 first-byte、actual duration、interrupt、cue miss 等 telemetry。

刻意不做

  • 不做全双工语音。
  • 不做 VRM 同权支持。
  • 不做太多 TTS provider UI。
  • 不做复杂 agent 行为编排。

P1 生命感与中文语音细化

2-5 个月

这一阶段的目标是让用户开始觉得“她不是播报器，而是在活着地说话”。

重点建设

  • 中文优先的 prosody profile、停顿、呼吸、语尾、轻重音规则。
  • 口型从纯能量驱动升级到 `能量 + phoneme/viseme` 混合驱动。
  • 表情系统增加 micro-expression、pre-utterance cue、post-utterance settle。
  • resident performance 与 quiet companionship 进入稳定常驻循环。
  • 建立“说之前、说之中、说完后”的状态转换图。

借鉴对象

  • N.E.K.O.：学它统一 TTS queue、可中断流式输出，但不要照搬三服务器。
  • Open-LLM-VTuber：学它对 interruption、first response latency、并发分段 TTS 的重视。
  • 你自己的 Alicization：把 `digitalLifeSpine` 真正变成 resident performance 的长期来源。

P2 半实时语音与陪伴闭环

5-9 个月

当桌宠式说话闭环足够稳，才把按键/按钮交互向半实时语音陪伴扩展。

新增能力

  • Push-to-talk 与短句 VAD 并存。
  • 半双工 interruption：用户插话即停播，角色平滑收口。
  • ASR 中间态驱动 anticipation animation。
  • 主动陪伴与静默陪伴统一进同一 director 协议。
  • 增加英语 secondary support，但不抢中文优化优先级。

风险控制

  • 不要把 ASR 中间态直接污染心智层。
  • 不要因为追低延迟把情绪和口型质量拉垮。
  • 保持“半实时”而不是急着上全双工。

P3 本地数字生命平台化

9-18 个月

这时再逐步把它从“一个很活的桌宠”推向“本地数字生命平台”。

可以进入的方向

  • VRM 作为第二执行栈接入同一 director。
  • 本地优先 TTS / ASR / 小模型 fallback。
  • 角色卡、声音包、动作包、表情包的内容层抽象。
  • 多端同步：桌面、Web、移动端共享心智，具身层按端能力退化。
  • 长期记忆、日常节律、主动行为进入“生活化系统”。

这时才值得考虑

  • 多进程/多服务拆分。
  • 远程 agent server。
  • 完整创作者平台。
  • 全双工实时语音默认开启。

一句话路线

推荐

先做一个非常像活着的 Live2D 中文桌宠，再把它平滑扩展成半实时陪伴体，最后才是本地数字生命平台。

最常见的失败路线

避免

一开始就想同时拿下 全双工语音、VRM、纯本地、平台化、多角色工作坊，最后每条线都半成品。
