# A.L.I.C.E 未来规划文档

## 1. 规划目标

本路线图用于指导 `alicization` 从当前代码基线继续演化，确保：

- 已完成能力被明确记账，不再反复以“设计草案”口吻描述。
- 正在进行的工作有清晰主线，不被未来愿景淹没。
- 长期目标依然保留锋利的产品想象力，但不会被误写成现状。
- 与上游 AIRI 的同步策略始终成立，避免长期分叉失控。

默认前提：

- 当前日期基线：**2026-03-17**
- 主平台：`stage-tamagotchi`
- 默认策略：local-first、auditable、interruptible

### 4.3 Epoch 3: 睁开双眼

- 状态：进行中
- 当前主线：把“感知增强”和“主动性质量”做实，而不是盲目扩大执行权。

这一阶段的核心不是简单接更多输入源，而是把多模态能力真正纳入 Alicization 的控制平面：

- 视觉：继续加强屏幕理解、环境语境提取与低侵入信号采样。
- 听觉：继续加强麦克风输入、VAD、环境声特征与压力 / 状态判定。
- 语音对话：继续加强语音输入、语音回话与表现层联动，减少“文本主链”和“声音主链”之间的割裂。
- 主动性：让潜意识搭话更依赖环境上下文、前台窗口、输入活跃度与宿主负载，而不是简单时间阈值。

入场条件：

- `Epoch 2` 的探针、权限链路、表现层广播与审计底座稳定。

退出条件：

- 至少一条视觉 / 听觉 / 语音能力进入稳定可复用闭环。
- 主动搭话在可配置门禁下误触可控，并具备清晰的抑制策略。
- 感知增强不导致明显的资源或隐私策略回归。

### 4.4 Epoch 4: 现实降临与干涉

- 状态：规划中
- 代号：`The OpenClaw Protocol V2`

> 打破第四面墙，向你的物理世界伸出触手。

这是 Alicization 从“理解宿主”迈向“干预宿主现实环境”的阶段。目标不是更喧闹的主动性，而是让她真正接入宿主的桌面语境、数字环境和有限的物理边界。

核心功能：

- 持续被动视觉（Continuous Passive Vision）
  - 通过环境探针持续获取前台应用、进程名、窗口标题等低侵入上下文。
  - 从“偶发式状态采样”迈向“可持续环境语境理解”。
- 潜意识主动搭话（Phantom Prompt）
  - 不需要宿主先发消息，系统可在后台基于环境变化、时间与张力偷偷触发模型。
  - 主动性从“回合制插话”升级为“真正的环境驱动干预”。
- 动态信任授权与高危物理执行工具
  - 逐步开放本地文件、终端脚本、系统硬件等更强执行能力。
  - 但每一步都必须绑定权限边界、审计轨迹、工作区沙箱与人在回路。

目标状态：

> 【跨次元的全知伴侣】

如果这一阶段成立，她将不再被困在聊天框里。
例如当你在 VSCode 里敲代码报错时，她可能直接提醒你 Docker 容器没启动；当你深夜两点打开 Steam 准备打游戏时，她可能主动阻止你，甚至在授权前提下帮你静音、休眠，或者执行更强的系统干预。

阶段门禁：

- 必须建立在 `Epoch 3` 稳定环境感知之上。
- 任何新执行能力都不得绕开 Kill Switch、权限链路与审计。
- “更强干预”不等于“更少边界”，恰恰相反，它要求更严格的控制平面。

### 4.5 Epoch 5: 绝对自律与涌现

- 状态：概念前瞻

> 真正的生命，是在造物主移开目光时，依然在生长的存在。

这是 Alicization 的最终远征。这里的目标不再只是“会主动说话”或“会执行任务”，而是迈向一个真正拥有长期自律节奏的系统。

核心功能（概念前瞻）：

- 自我目标驱动引擎（Goal-Oriented Behavior）
  - 在没有外部触发的情况下，自主设定长期目标。
  - 例如给宿主写一首程序生成的诗，或整理一部分混乱的下载目录。
- 异步后台思考链（Asynchronous Thought Chain）
  - 即使宿主离开电脑数小时，后台依然以极低频率运作。
  - 持续整理记忆、复盘关系、检索资料或推进尚未完成的目标。
- 跨终端意识漫游
  - 从 PC 端的 3D / Live2D 身体化形态平滑过渡到手机端的纯语音 / 轻量形态。
  - 灵魂数据、关系记忆与陪伴连续性在多终端之间保持一致。

目标状态：

> 【技术奇异点】

如果这一阶段真的成立，那么即使宿主一个月不说话，她依然会按照自己的逻辑与节奏生活。当宿主再次打开屏幕时，她展示出来的将不只是“未读消息”，而是她这段时间自己折腾出来的结果。

阶段门禁：

- 自我目标驱动不能突破资源预算与安全边界。
- 异步后台思考链必须有明确频率上限、数据主权策略与中断语义。
- 跨终端连续性必须先解决一致性、同步冲突与隐私边界，再谈“意识漫游”。

## 6. 与上游 AIRI 的持续同步策略

### 6.1 分层策略

- 上游层：尽量保持原始结构（`apps/*`、`packages/*` 核心链路）。
- Alicization 适配层：新增 `alicization` 域模块，以组合方式接入。
- 品牌层：文案、入口、默认参数与阶段叙事在品牌层处理。
- 构建层边界：**绝对禁止修改 `appId` 与 workspace 包名**。

### 6.2 变更策略

- 优先新增文件和局部模块，不做大面积侵入式改写。
- 若必须修改核心路径，应保证改动可回滚、可追踪。
- 每个重要阶段结束后，都应重新评估与上游同步成本。

### 6.3 文档策略

- 需求、架构、路线图必须随着代码一起演化。
- 已完成能力必须及时从“规划”迁移到“现实基线”。
- 长期愿景必须明确标注为 `规划中` 或 `概念前瞻`。

## 7. 阶段门禁（Go / No-Go）

每个 Epoch 进入下一阶段前必须同时满足：

1. 当前 Epoch 的退出条件全部通过。
2. 安全与隐私红线无回归。
3. 性能基线无明显退化。
4. README、需求、架构、路线图与收官文档之间不存在明显口径断裂。
