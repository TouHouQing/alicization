# Live2D 文字流与口型同步修复（2026-10-18）

## 结果与边界

文字模式接入实际显示字序驱动的嘴部控制：首字提交时开始，按中文发音变化，标点停口，取消停止剩余字序并清除嘴部输入。文字口型不生成音频能量，不逐字重启表情或全身动作。

**目前是整份回复通过结构与内容校验后逐字呈现，并非服务商原始 token 到达即显示。** 原有 JSON、私密思绪和最终回复的权威边界保持生效；这一点影响开始显示前的等待时间。

默认 Hiyori 实测主要只有 `ParamMouthOpenY` / `ParamMouthForm`，所以只能按发音进行简化投影，不能声称具有真人级或完整五元音几何精度。带 `ParamA/I/U/E/O` 或 Mouth 前缀参数的模型增加了对应绑定；参数选择、切换清零、只写真实编译参数有单独测试。本轮真实 GUI 使用 Hiyori，没有把模拟参数测试当成其他模型的真实体验。

中文使用上下文拼音；数字按普通话逐位读法；拉丁文字按拼写近似，没有新增英文音素词典或声学强制对齐；emoji 和符号保持静音。语音模式仍由实际音频主导嘴部。

## 原因与实现归属

1. 先前文字模式撤掉合成语音时钟后，没有独立的文字口型生产者，导致没有音频就一直闭嘴。现在同一个 `text-presented` 字序交给字幕、远端聊天和 Live2D，音频状态不承载文字假能量。
2. 旧发音辅助路径对大多数汉字按哈希选元音，不能支持内容一致。新文字路径使用 `pinyin-pro` 对完整汉字串解析上下文读音，按闭唇声母、韵母、复合韵母和标点规划嘴部；覆盖重庆、银行、重新等多音字用例。
3. `stores/chat/text-presentation.ts` 是唯一显示进度时钟，按完整 Unicode 字素处理，不拆开 emoji 或代理对。中文每字 110ms，拉丁字母 55ms，标点 170ms。取消可打断等待，旧轮次不再继续发字。
4. `ChatStreamEvent` 与 hooks 定义字序事件。跨窗口只传字序、读音和轮次身份，避免每个字复制整份历史与提示词。`token-literal` 保持原有语音流水线输入职责。
5. `stage-shared/stage-text-articulation.ts` 负责文字嘴部形状；Live2D `text-mouth.ts` 在 Cubism 最终绘制阶段投影到模型真实编译参数。缺失参数不会通过 SDK 虚拟 ID 伪装执行。真实音频拥有嘴部优先权。
6. 实测还发现后台帧率低时，受限的平滑步长拖慢上一有声元音的回落。失败记录观测到真实静音期间嘴部开合 0.216863。修复为真实音频静音时直接采用当前非言语嘴部目标，去掉旧音频平滑尾巴与原生动作嘴部混入，没有放宽静音门禁。

显示进度属于对话呈现，发音形状属于身体投影，语音由实际音频驱动；情绪和主要动作仍由同一轮权威表演元数据管理。

## 已完成的编译版验证

- 798 项测试、58 个文件通过；全项目 typecheck 与 lint:fix 退出码 0。仓库既有 725 条 ESLint 和 7 条 Oxc 警告未作为无关重写对象。
- 最终文字诊断：45 条检查通过，实际配置服务商回复、聊天 DOM 首字没有提前泄露剩余回复、实际绘制嘴形区分啊/衣/乌、逐字输入与显示字序对应。
- 最终语音诊断：39 条检查通过，真实 SAPI 与实际 PCM，含播放中断、旧音频不复活、静音嘴部、下一轮点头。静音采样 28 帧，待机/前台动作中的最大嘴部开合分别约 0.099 / 0.080。
- 取消专用诊断：39 条检查通过。在文字已显示后点击中断，字数不再增长，嘴部输入清空，下一轮动作正常。
- 所有 GUI 均在独立 Windows 桌面，输入桌面仍为 Default，没有切换或覆盖主桌面；正常 UI 退出与日志排空有独立记录。

首字检查分别观测实际提交给 Vue 模型的嘴部输入和后续最终绘制。并行软件渲染压测下，低帧率可能跳过一个 110ms 字素的最终绘制，因此不能把“没有采样到首字画面”当作“首字没有输入”，也不能声称每一个字都在低帧率硬件上被完整绘制。

保留了三类诊断失败记录：取消专用诊断错误复用固定元音场景断言，后按场景限定；真实静音残留修复前的 PCM 失败；低帧率未采样到首字后增加独立提交输入观察。正式元音和静音数值门禁没有放宽。

本轮不作为长期人格、记忆、执行策略或完整数字生命闭环的验收。
