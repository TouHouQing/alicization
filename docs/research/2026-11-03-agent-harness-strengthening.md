## 已修复的问题

### 工具结果挤满本轮上下文

基线保留当前用户消息之后的全部工具输出。即使旧对话已经移除，连续读取多份日志仍会在下一次模型请求前抛出 `PROVIDER_CONTEXT_BUDGET_EXCEEDED`。

现在预算紧张时只缩减模型视图：保留原始调用参数、调用 ID 和结果配对；输出引用包含原始 SHA-256、字节数、有限首尾预览及分页方法。原始 `action.observation` 和结算事件留在已有 SQLite 事件仓库。

`life_read_tool_observation` 通过普通工具注册、生命行动登记和执行检查，按当前角色、真实会话、本轮、调用 ID、原文哈希和已完成结算读取。用户不能通过参数指定其他角色或会话。读取采用 UTF-8 字节偏移，每页 64～8192 字节；取消、哈希变化、未结算、重复或不存在的回执均拒绝。回读不会重新执行原始操作。

更早的预览可进一步缩为原始引用，保持同一个来源哈希。最新分页结果优先保持可读，防止反复读取“分页的预览”。压缩保留结果状态和错误码，避免把失败遗忘成成功。没有提供回读工具的请求仍会明确报告预算不足。

### 长任务过早停止与重复失败

主对话步数上限从 16 调整为 64，同时保留已有取消、超时和副作用不确定性约束。执行满 63 次提议后，下一步只允许形成最终回复。

`agent-harness/progress-context.ts` 从本轮实际调用和回执派生近期进展，不另建任务状态。相同操作、相同规范化输入和相同错误连续出现两次时，给下一步提供调整计划的约束；三次后移除本轮工具调用能力，让模型说明真实阻塞。成功、输入变化、错误变化和新用户回合会重新计算相应状态。此机制不会绕过未知效果核验、重复派发检查或危险操作审核。

### 已学会的方法不易在新任务中使用

会话准备现在从原有技能权威取得当前方法目录，仅向模型提供与本次请求相关的少量方法元数据。最多四项，方法数组最多 3000 字节；目录不包含旧路径、原始内容或可执行脚本。

只有来源有效、独立评测通过、当前启用的方法能进入目录。匹配涵盖中英文及操作领域，不把不相关的陪伴对话改造成执行任务。实际使用仍先查询完整参数接口，再经过版本、来源、权限、鲜活参数、任务计划和独立验收检查。撤销或验证失败的方法不能因旧目录而继续执行。这是改善既有经验的发现与使用，没有新增模型权重训练或未经评测的自动激活。

## 验证及适用边界

直接回归覆盖预算、完整会话准备、方法撤销、主循环、执行工具和分页引用；跨系统回归另覆盖技能生命周期、计划修订、结果核验、方法失败撤销及角色状态投影。最终命令、结果和限制见同目录 `2026-11-03-agent-harness-validation.json`。

联调使用真实本地 HTTP SSE 服务、生产主循环和 SQLite，逐页还原包含中文与 emoji 的大段原文，并检查原始操作只运行一次。另验证十八个连续行动可完成，以及三个相同失败之后不再授予行动能力。测试在后台运行。

这些证据验证本轮运行时改造，不等同于真实外部模型能力排名，也不替代原先尚未关闭的真实 CLI、物理键鼠、混合 DPI 和当前安装包验收。模型自身的规划能力、输入窗口及工具理解仍会限制实际表现。
