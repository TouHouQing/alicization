# An owned artifact receipt must describe only what the adapter observed

The actual v318 invited-creation database contains a verified fictional story and its correctly bounded creative episode, but also a generic execution episode saying an interest note with source citations was organized. The shared owned-note adapter supplied that description for every output, including stories and passive SVG. A file hash proves bytes, not genre, citations, research or a new creation when an identical immutable file already exists.

The adapter now reports only successful local content verification. Cancellation and failure descriptions also refer to the local artifact rather than inventing an interest note. Exact file ownership, immutable creation/reuse, independent hash verification, partial-effect uncertainty, source withdrawal and stop semantics are unchanged. The project runtime remains the owner of genre-specific creative experience and its fiction boundary. Historical episodes remain historical evidence; this change does not rewrite past memory.

The real personal-project integration now additionally checks that the actual authored effect's durable summary cannot claim an interest note or source citations for a fictional story. On the previous adapter one case fails and the other passes (output/execution-v320-artifact-summary-red-20261101-pass2.json). Pass1 accidentally selected no cases and is retained as unexecuted evidence, never a RED or a passing validation. After repair the unfiltered personal creation, actual content/reopening/withdrawal, project-memory and invited-creation group passes23 checks. Desktop types, lint and current package acceptance are recorded separately; this worktree change is not yet present in the v319 package.
