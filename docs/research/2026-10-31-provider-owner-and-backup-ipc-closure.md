## Provider request ownership

The real providers Pinia store now owns independent validation, model-list and instance operations under the current credential generation. A synchronous deep credential watcher revokes even A→B→A edits in one tick, deletions and reset. Requests receive JSON snapshots of the persisted configuration, including nested headers. Stale operations cannot publish configured state, models, errors, loading or backoff. Validation alone owns its result/backoff, so periodic and whole-store callbacks cannot apply an obsolete result again. A deliberate bypass revokes older checks.

Concurrent creation for one current connection is deduplicated. Obsolete created instances are disposed and rejected. Disposal detaches the cache before awaiting teardown, so it cannot erase a replacement. SDK instances retain their raw identity; scope disposal revokes pending owners. This is result invalidation, not a claim that provider APIs lacking AbortSignal cancel their network traffic.

Eleven original real-store tests reproduced failures before repair. The final store has fifteen focused cases, including reset, same-tick credential/model changes, scope closure and explicit disposal during creation. Full shared UI regression passed **1417 tests, 0 failures, 3 skipped**. Shared UI and desktop Node/Vue typechecks and scoped lint pass. These are real store orchestration tests with controlled external provider callbacks; they do not prove the remote service is available.

## Backup IPC closure

The shared Valibot command schema now owns both the inferred TypeScript command and trusted IPC parsing. It preserves UUID and manifest digest checks and adds bounded cursor (1–512 chars), integer page size (1–100) and boolean refresh.
