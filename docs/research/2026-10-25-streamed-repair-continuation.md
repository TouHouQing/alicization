# 流式回复的私下续文修正

目标是保持同一条话语及身体表达的连续性，同时保留执行事实和记忆入库的证据门。

## 跨工具动作的同一句话

真实 localhost HTTP SSE 暴露了此前受控回调没有覆盖的顺序：当前 xsAI 0.4.3 在收到 wire `finish_reason=tool_calls` 时先发 `finish`，待网络 EOF、参数解析完成后才发 `tool-call`。主循环原先遇到前者就停止读流，导致工具调用丢失。修复改为：若 finish 先于工具提案，则继续读取到 EOF，保持续行 watchdog，检查完整参数、registry 和单动作约束，再交由现有 EventLoop 受理。SDK 仍只拿到 proposal stub，不能执行实际工具；缺失提案、双提案均拒绝。

普通对话已经公开的开场白不禁止后续受理工具，但仍禁止重试和改写前缀。实际工具后的请求收到同一 `unpublished-continuation-v1` 事实块，正文只生成未公开续文；整句再次通过结构、closure 和 grounding。事实回复从首字起保留证据门，工具执行、结果回写及学习仍由各自既有 owner 负责。修正文段同样复用该事实块，避免重复注入。

受控动作续接82项通过后新增真实 HTTP 验证先失败：只收到第一条请求，未进入执行。修复后两文件186项通过，含实际 SSE 开场白先公开、工具一次、第二次请求包含真实工具结果及唯一前缀事实、同一条回复只追加一次续文。另含 xsAI finish 后单提案、双提案、缺失提案，以及没有 EOF 时 watchdog 仍生效。日志为 `output/execution-tool-finish-continuation-20261025.log/.json`；初始失败保留于 `output/execution-action-http-continuation-20261025.log/.json`。最新类型、构建、Live2D 完整组合仍待复验。

## 实际失败

`output/execution-artifact-observation-live2d-20261025-pass90/report.json` 在129项处失败。只读数据库确认，同一聊天 turn 的两次 review 均被拒绝；不能误用后续 execution-callback 的 accepted review 认定聊天修正已通过。第一轮把“我会按原参数执行；”判成未绑定操作。实际已公开4字“计划已接”，修正模型返回“计划已接我还没完成这份下载：计划刚被接收，”，第二次整句仍被拒绝。失败直接原因是 grounding 拒绝，而非前缀不匹配异常。

另一个完整体验 pass89 在产物检查时读到已创建但尚未写完的文件；原始失败保留。其后只修验收脚本，使其在原45秒期限内等到精确期望内容，详见 artifact-acceptance-race 文档。没有把该失败追认为通过。

## 实现

当本轮已经公开前缀，修正请求显式采用 `unpublished-continuation-v1`：保留原输出对象结构，reply 字段只承载尚未公开的续文，包括补完未结束的词。本地主进程持有前缀，对修正原文先做结构和记忆引用校验，再组合规范化对象。整个组合仍通过原 settlement、closure 及第二次 grounding，只有通过后才能追加、归档和学习。重复前缀、无效结构、超长组合或未证实含义仍失败；工具禁用、单次修正、没有公开文本/情绪回调，也不重放已执行动作。

没有公开前缀时仍由模型生成完整修正。原始已显示前缀不会因续文合格而自动成为事实证据。

“参数”加入已有计划指代语法；仅允许绑定当前可继续的计划，不允许其他参数或附加动作。停止、完成、错误绑定及混合肯定继续受原有条件约束。
