# Common Windows Save As filename continuity

Phase1 execution must validate the application's actual output, including a Windows system file dialog. A successful UI Automation call and visible filename are insufficient evidence of a successful save.

An actual `System.Windows.Forms.SaveFileDialog` using the modern Windows common dialog reproduces a mismatch. UI Automation replaces the filename edit text with a new Chinese/emoji path, and fresh observation returns that exact new value. Invoking Save nevertheless returns the initial filename and the real fixture writer creates `initial-2.txt`. The independently requested output is absent. Both failed attempts retain the observed field, selected button, application receipt and normal fixture exit. The first harness attempt also exposes a separate asynchronous receipt race; its failure remains recorded.

The filename edit is a native `Edit` child of `ComboBox`, followed by `FloatNotifySink`, `DirectUIHWND`, `DUIViewWndClassName` and the owned `#32770` dialog. Changing its text does not deliver the combo notification the shell uses to update its filename state. The worker now sends one bounded `CBN_EDITCHANGE` notification to that observed combo's actual parent after setting the edit value. It requires both the edit and notification receiver to remain inside the exact observed top-level window and checks the dispatch deadline. It does not move focus, inject global keys, click Save, or retry the action.

The notification follows the documented native control protocol: [Microsoft CBN_EDITCHANGE](https://learn.microsoft.com/en-us/windows/win32/controls/cbn-editchange), [combo-box messages and notifications](https://learn.microsoft.com/en-us/windows/win32/controls/about-combo-boxes), and [edit-control messages](https://learn.microsoft.com/en-us/windows/win32/controls/about-edit-controls). The independently observed failure, rather than the documentation alone, establishes why this project needs the notification.

The repaired native pilot passes one cancel and three actual Chinese/emoji filename saves. The requested paths and exact UTF8 writer content match. The cancel leaves its proposed output absent. An inactive private desktop preserves the host's input desktop throughout, and the native fixture exits normally. A further qualification retains those checks and adds expired authority, stale filename and changed popup-owner refusals. Unit/interface tests, other native controls, the current compiled worker literal and packaged experience remain separate required evidence.

Fixture source uses encoded UTF16LE PowerShell execution so Windows PowerShell5.1 preserves its Chinese literals. The harness waits for the application receipt from the single original click; it never clicks again to compensate for asynchronous modal closure. It retains the initial race failure rather than classifying it as a product defect.

Scope is an actual common-dialog native capability with synthetic approvals and owned output paths. It does not certify a complete real-model dialog workflow, overwrite-confirmation variants, physical user takeover, interactive menu capture or mixed-DPI behavior. It does not declare all EX00–EX23 acceptance complete.
