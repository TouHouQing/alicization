# 2026-10-14 产品体验与缺陷检查

本轮从新的合成身份重新首启，通过真实界面完成操作，重点检查“看得懂、找得到、点得动、失败后能恢复、保存后能续用”。桌面核心继续遵循 Phase 1 的身份、记忆、关系与身体一致性规则；没有用注入人格或伪造模型回复来代替体验。

## 发现与修复

| 问题 | 原表现 | 本轮修改与验证方式 |
| --- | --- | --- |
| 直接打开设置子页无法返回 | 首启引导打开动作映射后，返回按钮没有路由历史可用 | 无历史时返回存在的父路由；实际从首启进入并返回设置首页 |
| 模型选择跳过确认 | 选中模型即自动进入下一页 | 只由“保存并继续”提交，实际选择后检查仍停留本页 |
| 配置的服务在设置中消失 | 首启保存的对话服务没有登记到服务列表 | 显式登记并恢复已有配置，实际进入意识模块检查 |
| 配置失败缺少可读的恢复路径 | 英文帮助、原始 HTML 错误、空地址也能继续 | 中文恢复说明，技术详情折叠，拒绝空地址，重试与返回可用 |
| 聊天没有明确发送入口 | 用户只能猜测 Enter 的行为 | 增加发送按钮、空态、快捷键说明与等待反馈，真实调用模型 |
| 连续发送与输入法确认 | 等待期间重复 Enter 或配置准备期间快速点击可能重复提交 | 准备与流式阶段都有互斥，输入法组合 Enter 保留，失败不覆盖新草稿 |
| 角色卡导入失败不反馈 | 文件不合法时只记控制台错误 | 校验实际消费字段，界面显示错误；非法 JSON、空对象与有效卡分别操作 |
| 拖放与上传文案失效 | 缺少 dragover/drop 处理，中文插槽被组件忽略 | 正常转发插槽与拖放文件，通过实际 DataTransfer 路径验证 |
| 编辑卡片偷偷切换人格 | 打开非当前角色卡的编辑器即激活她，取消也无法还原 | 编辑只改模块绑定；人格与记忆须先显式激活；取消和保存均核对原活动卡 |
| 设置分类反复折叠 | 看完一个服务返回后，展开状态全部丢失 | 分类会话内持久化；修复可选 Boolean 被自动转成 false 的组件问题 |
| 内置服务入口打开空白页 | 不发声、本地语音、本地听觉没有对应服务路由 | 指向已有语音/听觉模块入口，保持服务选择与实际启用分离 |
| 多处暴露翻译键 | 记忆、语音服务、关于、嵌入窗口显示内部 key | 修正命名空间与字段位置；检查正文、输入提示和文本框默认值 |
| 模型列表名称被裁切 | 窄窗口大图占满列表，看不到名字和确认 | 两列预览、可滚动名称与固定确认入口；实际切换 VRM 与 Live2D |
| 关于页重复链接与横向滚动 | 内嵌默认英文链接与页面链接重复，宽度按完整视口计算 | 去掉重复区域，使用容器宽度，标题在窄窗口换行；检查内部滚动容器 |
| 未检查就声称最新版本 | 初始 idle 状态展示“已是最新版本” | 只有确实收到 not-available 才显示最新，禁用时明确显示已禁用 |
| 空小部件窗口没有关闭入口 | 空态是技术提示，关闭控件只在内容存在时出现 | 可读空态、等待反馈，关闭入口始终存在，实际关闭空窗口 |
| 数据操作结果不可见 | 已计算成功反馈但模板没有渲染 | 渲染 status/alert；实际导出、非法导入、有效导入与重新载入 |
| 多窗口操作后退出残留 | 窗口已关闭，后台进程继续等待 | 先完成生命与窗口退出钩子，再关闭依赖服务；日志写入有序排空、拒绝关闭期间的新写入，正常退出单独记录时长 |
| 浏览本地语音页触发下载且失败无回执 | 打开 Kokoro 页即下载；Worker 异常没有响应，界面可能等待两分钟 | 改为显式载入、进度与失败重试；Worker 错误回传、清理监听器，真实界面注入断网检查 |
| 选择控件的禁用与默认项失效 | Select 未透传 disabled/placeholder，本地模型首次显示空值，通用表单还展示不需要的密钥字段 | 向实际输入与展开按钮传递状态，使用同步本地模型目录提供首帧选项，隐藏本地服务的密钥输入；核对可见默认名称与载入期间禁用 |

## 体验覆盖与证据

- 原包手工式逐步操作记录：`output/product-audit-20261014-round2/`、`output/product-audit-20261014-round3/`。第三轮包含 83 份操作记录，覆盖设置入口、模块、记忆页签、人格、主动节律、备份、模型与对话取消。
- 自动化完整操作：`apps/stage-tamagotchi/scripts/life-acceptance/life-product-regression.cjs`。每次都从新的合成身份走人格初始化及服务配置，不直接调用聊天 store 来制造回复。
- 相关回归：14 个测试文件，235 项通过。新增 Kokoro 操作失败、重试、生成恢复、Worker 崩溃与超时检查，以及日志关闭期间的写入排空、并发关闭和失败检查。选择控件检查真实输入和展开按钮的禁用状态与默认名称。
- 完整工作区 `pnpm typecheck` 通过；后续桌面类型复查通过。`pnpm lint:fix` 无错误，有 725 条工作区警告。
- 失败记录保留：dev—dev5 的分类、角色激活、翻译及退出失败；dev6—dev7 是测试工具的 Windows 身份核验失败；dev8—dev9 捕获 Kokoro Worker 下载异常；dev10 界面通过但退出未完成，不能算最终通过；dev12 的模型/声线双控件定位歧义修正后，在最终包完整复测。强制清理不会改写为正常退出。
- 最终解包版从新身份完成 97 个界面状态、79 项检查，全部通过。实际模型回答使用同一个人格名称；聊天导出/导入及重新载入保留对话；Kokoro 浏览零下载、断网失败及时回传、可重试且载入时禁止切换模型。正常退出耗时 390 毫秒，退出码 0。证据：`output/product-regression-20261014-packaged/report.json`。

两处较旧的主动性测试样本包含没有原始事件依据的往事或行为声明，回复证据核验正确拒绝了它们。本轮将正向反馈样本改成当前场景描述和询问，并固定白天时钟；没有放宽产品的证据或安静策略。

## 测试隔离

所有 GUI 运行于独立 Windows 桌面，没有切换输入桌面或操作用户桌面。按钮检查通过可见控件触发 Vue 事件链；托盘辅助窗口调用实际菜单回调。明确使用软件 GL 和静音，截图仅来自自己的应用窗口。

测试运行器登记准确 Electron PID、可执行文件、合成档案与继承的桌面身份，再收束到自己的 Windows Job。实现依据 [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 与 [AssignProcessToJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject)。它没有按进程名批量终止用户程序。网络通道使用独立 QA 端口与合成身份中的连接偏好，避免连接到正在运行的其他实例。

凭据只临时用于合成身份的真实服务配置。报告脱敏，正常退出后移除该身份的凭据与 Local Storage；清理缓存时保留失败记录、合成人格、数据库与截图。

## 尚不能宣布通过的范围

1. 服务目录的入口、布局、文案和返回路径可以逐项检查；所有付费供应商连接、OAuth、语音听感与硬件麦克风仍需相应账号和设备环境。单个实际对话模型成功不代表每个供应商成功。
2. 私有桌面截图能证明 VRM/Live2D 在该环境绘制，不能代替 Default 桌面的物理点击穿透、游戏覆盖和 GPU 环境验证。本轮保持用户主桌面可用。
3. 记忆质量、人格训练、能力与审计页面仍偏工程工具，说明密度较高。访问与错误修复完成不意味着普通用户已能无学习成本使用这些高级工作流。
4. 视觉、Minecraft、Discord 等带 WIP 标记的页面不是已经闭环的日常能力；不将“页面可以打开”算作功能完成。
5. 本轮是产品缺陷检查，不证明长时间陪伴、真实主观意识或全部 Phase 1 指标已经成立；实际自然主动性和长期连续性须保留各自的持续使用证据。
6. 本轮生成新的安装器，实际启动验收的是同发行目录中的解包版；安装与卸载流程没有在本轮重新执行。

发行源码基于本地提交 `7880afc29ab33a4cf4de89f7a6610664278494c3`，包括之前尚未提交的开发成果与本轮修复。源码指纹、ASAR 指纹和安装包指纹单独记录，不能把它称作未经修改的远端提交。
