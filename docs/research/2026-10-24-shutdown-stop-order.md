# Shutdown stop order

Actual Live2D combined pass81 required forced QA cleanup after sixty seconds. Its state hooks and window/flush markers appeared, but native exit was not established within the deadline. That failure is retained. It prompted inspection of two independently reproducible cancellation-order defects; it does not prove either was the sole cause of the native timeout.

Bulk dialogue cancellation previously awaited each turn before requesting the next. A blocked or rejected first cancellation could therefore leave other turns running. It now snapshots the running owners, requests each owner's existing cancellation protocol immediately, and waits for all results. A rejected cancellation remains an error. A turn whose committed reply wins cancellation remains untouched; the function never aborts that turn's controller or fabricates a cancelled result.

The application shutdown hook previously awaited file-recovery, learned-procedure, browser and work-plan drains before cancelling providers and memory recovery. Those stop requests now begin before the first awaited drain. Dependencies and SQLite still remain available until owner cleanup and the existing settlement stages finish. No native writer is declared stopped by a request alone.

Three bulk-cancellation RED cases reproduce a gated first owner, already committed authority, and a rejected owner. A runtime-composition RED case starts the actual chat IPC path with a controlled provider and holds file-recovery disposal; the provider was still active at that drain. The complete two-file suite passed 182 tests after the changes. The first Node typecheck found four missing key arguments in the new test fixtures; those arguments were corrected. Final typecheck, selective primary integration and actual native shutdown revalidation remain pending.

The final drain composition starts all execution-owner disposals before awaiting their results; a failed owner is surfaced after the other stop requests have started. The held-recovery test also verifies that work-plan disposal has started. A separate failed-recovery test verifies that work-plan disposal still runs and SQLite is not closed underneath unresolved ownership. The final complete two-file suite passed 183 tests and Node typecheck pass3 passed, with zero lint errors. These are controlled owner-order proofs. Native shutdown after this change is still pending; pass81 is not retroactively accepted.

Primary v114 revalidation subsequently passed ten files / 307 tests, full desktop Node/Vue types pass91 and build pass90. Actual combined Live2D runs pass84 and pass85 exited normally in 490 ms and 1217 ms respectively, but failed their product workflows and remain rejected as full acceptance. The render recovery native pass4 on v116 production also exited normally in 1061 ms after a real WebGL fault/retry. These close the measured normal-shutdown checks; they do not establish the full owner fault matrix or explain pass81's timeout retroactively.
