## 已接通的工作流程

1. 模型通过生产工具接受明确的工作，先固定验收条件，再建立同一根责任的依赖计划。
2. 工作在有界窗口中推进，保存已观察的步骤结果，通过新的 task-run 接续，不复用已结束的聊天授权。
3. 后续步骤可以绑定前一步已提交的真实观察；实际派发参数还会在同一数据库写事务中再次核对。缺失、重名或越过依赖的引用会拒绝执行。
4. 写入后独立检查文件内容、结构或目录成员。单次操作完成不会直接把根目标标记成功。
5. 界面支持继续、暂停、取消、打开部分文件，以及修改未完成步骤的文字和路径。修改计划保留已观察的步骤；不能借换版本重放写入或隐藏未明结果。
6. 主人验收绑定实际交付文件版本，重载后仍保留。主人确认可以完成相应主观条件，但不会被当成独立成功经验。
7. Live2D 接收真实执行与完成状态；心跳延长当前状态，不重复启动手势或制造说话口型。
8. 总开关、系统休眠和退出连接后台任务中断。实际派发前重查来源、参数、归属、取消和资源租约；跨请求与重启的未明写入也会挡住同资源后续写入，包括硬链接别名。

本地目录工具现可在没有外部 MCP 服务时使用。它限制条目、返回字节、目录数和深度，不进入嵌套链接，并明确标记截断。精确目录成员验收与文件内容验收具有不同证明范围。

## 真实体验发现和修复

| 实际现象 | 原因与处理 |
| --- | --- |
| 同一工作显示两张卡片 | 根责任同时进入旧责任列表和新工作列表；统一了展示入口。 |
| 点击确认长时间没有反馈 | 请求在一次约 40 秒的后台反思之后排队；显式工作控制优先处理，快照读取可共享同一角色的作用域。 |
| 操作结束后页面仍显示旧状态 | 成功提示先于异步刷新；控制按钮现在等待实际视图刷新完成。 |
| 修改后可能再次执行已完成写入 | 新计划没有继承已观察结果；事务现在保留结果并禁止修改已观察步骤。 |
| 后续浏览器步骤只能填写猜测的引用 | 加入真实依赖观察绑定，并在派发和结果提交时核对。 |
| 浏览器重新观察后字段证明失效 | 把一次观察的 opaque ref 当成稳定证明 ID；区分了派发引用与核验身份。 |
| 第四个工作请求未发送就失败 | 全部工具定义与完整记忆超出预算；明确指定工作计划工具时，仅提供对应工具，完整身份、记忆、当前输入保持在请求中。 |
| 修复体验停在“读取文件” | 应用正在等待真实路径审批；验收脚本现在核对实际审批弹窗的目标和操作后继续。聊天历史中的路径不作为审批证据。 |
