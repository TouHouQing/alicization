# 长期人格成长开发与验收

本轮完成了长期人格成长的工程链路：已确认经历 → 独立来源 → 情境假设 → 小幅试行 → 对应互动的真实反馈 → 有边界地采纳到 SOUL。SOUL 仍是已采纳人格的权威；候选、证据、情绪和执行技能各自保留清晰归属。

## 已交付的行为

- 同一次互动的反思、强化和整理不会重复算作独立经历。旧版自我投影也记录近期来源根，记录窗口或整理措辞变化不会反复推动性格漂移。
- 假设区分自身兴趣、相处习惯、表达风格和工作方式，并保留适用情境、例外、正反证据及来源版本。
- 自身兴趣需要真实表达过的选择，以及实际执行、独立核验和作品归属。由用户爱好启发的自动练习明确标识为探索，不自动成为她自己的长期爱好。
- 本地适应、核心人格修订和模型权重训练解耦。训练权限继续单独检查；核心修订仍需成对评估和明确人工复核。
- 一轮对话最多试行一项变化，效果限制在很小范围。仅对应回复的结构化反馈能判定试行结果；普通强化不算成功，被打断属于结果未知。负面反馈可以反对旧做法，也可以支持新的改进假设。
- 满足独立事件、跨日经历、持续时间和成功试行门槛后，才准备精确的 SOUL 变更。自动适应不能修改稳定身份、手工边界或执行权限。
- 对话读取同一人格投影；成熟偏好影响已有主动行为候选的排序及 Live2D 的表达克制程度。情绪含义、动作选择和口型继续由其原有模块负责。执行结果和风险策略维持独立核验。
- “生命与约定 → 成长与经历”支持查看来源原文、补充例外、重新观察、暂停、继续和撤回。暂停保留成熟人格；纠正后的新版本必须重新积累证据，历史成功不能直接晋升新结论。
- 来源遗忘会撤回派生人格，清除其可读派生文本并阻止重放。SOUL 写入期间来源失效时恢复精确旧版本；并发人工编辑受到保护。成长暂存副本在成功或失败收尾后清理。
- v7 数据库升级到 v8 前生成一致的 SQLite 恢复备份。旧关系状态得到保留，备份保留原 schema 版本。

决策采用最近 16 个有证据的日期、每天最多 8 个独立见证；完整来源根账本继续保留，用于去重和审计。单日大量对话不会把所有跨日证据挤出决策窗口。当前门槛是工程策略，不应解释为意识或人类人格的科学判定。
