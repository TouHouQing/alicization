# 嵌套框架点击与方法受理核验

本轮仍属于 Phase 1 的可靠执行和连续对话闭环，不代表 EX00–EX23 全部完成。

## 点击位置必须在悬停后仍属于同一控件

实际 Chromium 反例证实：一个嵌套框架中的按钮在 `mouseenter` 时向下移动 90px，把相邻按钮放到原位置。旧实现虽然再次检查了控件的标签和身份，却沿用原坐标按下，造成 `saved=0, other=1`。RED 证据保存在独立工作区的 `output/execution-nested-frame-red-20261025-pass2.json`。

`execution/browser-cdp.ts` 现在在悬停后的语义核对之后，再次读取实际节点、内容四边形和命中节点。中心坐标改变超过 0.5 CSS px 就返回 `LOCAL_BROWSER_STALE_TARGET`，不发送按下事件。原观察、文档、后端节点、授权及输入释放保护继续适用。

真实无界面 Chromium 的五个场景包括：双层缩放框架的 Unicode 输入和可信点击、同名同 selector 的文档替换、悬停移位、祖先遮挡、焦点跳到顶层。加上原浏览器及 CDP 回归，三文件 11 项通过。它们不能替代跨进程 iframe 的原生验证。

新增 `browser-frame-input-probe.ts` 使用真实 Electron 隔离桌面和 `site-per-process`。127.0.0.1 → localhost → 127.0.0.1 的两层框架实际处于不同渲染进程。独立工作区三轮 38 项通过，验证精确多行中文/emoji、顶层字段不变、可信点击及悬停移位后无额外邻居点击；窗口全部关闭、进程正常退出，输入桌面始终为 Default。证据为该工作区 `output/execution-browser-frames-native-20261025-pass3/`。

第一次原生探针因本地 HTTP 连接未收尾而超时；失败证据保留。第二次明确失败，且发现 `process.exitCode` 配合 `app.quit()` 未向外传递失败退出码；现先保存报告、关闭自有连接和窗口，再以非零码退出失败。第三次报告和外部退出回执同时通过。单独的退出码从不替代报告断言。

本轮尚未验收所有跨源授权、框架移除/跳转竞争、滚动和 popup 组合，也不证明宿主物理键盘能力。

最终同一探针源码再次取得三轮 38 项通过，并注入“私有窗口登记后失败”的独立反例，核对失败报告、关闭所有自有窗口及真实非零退出码。验收摘要复制到主目录 `output/execution-browser-frames-native-acceptance-20261025.json`。第二次原生运行没有使同一子 widget 的鼠标离开目标，反例未触发；最终探针通过同一子 widget 的实际输入移开鼠标，并独立确认 handler 已运行，才检查停止点击。两次失败均没有计为通过。
