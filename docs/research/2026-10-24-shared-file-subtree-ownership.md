# Shared file objects and owned filesystem subtrees

This isolated EX09 continuation addresses a real alias hole between native download directory ownership and ordinary file operations. It is not full popup/transfer acceptance.

A real hard link created outside an already-owned directory names the same bytes. Lexical subtree checks cannot see that relation. The RED regression held the production resource broker's native subtree lease, created an actual outside hard link, then used the normal life writer/filesystem/backup adapter to overwrite it. The write incorrectly succeeded before the fix.

The host's resource resolver now records `file-shared-inode:<device>:<inode>` for regular files with more than one hard link. A file with multiple links but no observable inode is rejected. Resource overlap treats a shared object as conflicting with a tree owner in either acquisition order. Without a complete alias inventory, this conservatively defers shared files against any owned subtree. It does not assert that every such file is inside that particular tree.

An unrelated ordinary file remains executable during native ownership. Unconfirmed or uncertain native ownership keeps the alias blocked. After the native owner is confirmed stopped and its resource settled, ordinary hard-link writes remain supported. Normal inode locking still serializes different names of the same file. The life journal retains the host-derived resource snapshot; no model-provided path list owns this classification.

The first GREEN set passed 11 tests using actual SQLite, files and hard links, including both acquisition orders, unknown ownership, independent file progress, stopped-owner release, source snapshot recovery and persisted native download ownership. The frozen worktree v11 then passed all 64 execution test files (276 tests) and desktop Node typechecking; its source fingerprint was verified unchanged. Four reviewed files were selectively merged into the primary checkout with original-file backups and SHA256 baseline checks in `output/execution-shared-file-tree-reviewed-merge-20261024`. Primary composition subsequently passed 64 files / 288 tests. Frozen primary full regressions pass12 and pass13 passed 934 files / 8181 tests; pass14 passed 935 files / 8187 tests, with the same 12 opt-in skips. Source hashes matched after each full run. These checks include this policy, without establishing the broader fault matrix below.

This is a conservative conflict policy, not a complete OS alias inventory or kernel lock. It does not implement popup ownership, physical takeover, arbitrary external-process mutation prevention, or the full transfer fault matrix. A host-created alias during an already-dispatched syscall can still require unknown-outcome reconciliation. Those broader EX09/EX21 limits remain open.
