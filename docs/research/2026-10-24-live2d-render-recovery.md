# Live2D renderer recovery

Combined native QA pass84 exposed an actual unsupported WebGL renderer: no Live2D model was mounted, while the desktop remained on its preparing indicator. That run failed and remains rejected. Selecting Live2D is not evidence that a body was drawn. The main product harness now requires an actual mounted model and an advanced draw frame before task acceptance.

Canvas owns renderer construction, drawing, resize and context-loss failures. It unpublishes the model slot, stops the ticker and emits a bounded failure code. The scene and shared stage forward that same code. The stage cancels its own drag/wheel interaction; the desktop presents localized failure/retry controls and reports the code through its existing body-health owner. Recovery captures only its hovered panel, not blank desktop pixels.

Retry joins simultaneous requests and flushes model teardown before destroying the old Pixi application. Stale callbacks cannot stop a newer owner. Failed destruction retains the old owner for a later retry. A pending retry cannot create a renderer after component disposal. Renderer state remains loading until the actual model and canvas are mounted; no health pulse is fabricated.

The original four canvas failure cases, interaction cancellation and desktop capture tests passed 32 checks in the isolated worktree. The Live2D package typecheck passed. The worktree desktop typecheck resolved its package junction to the primary checkout, which still had the old scene API; it failed and is not counted as accepted. Ten reviewed files were selectively copied with a v115 hash guard and original-file backups. Primary validation passed 33 tests, including an additional failed-resize lifecycle, full desktop Node/Vue typecheck pass92, Live2D package typecheck and build pass91. Frozen v116 source verification found no changed or added files after those checks.

Private desktop tests may explicitly request SwiftShader to provide a renderer without switching the user's input desktop. Such a positive test does not establish hardware GPU support. Native probes pass1–3 attempted `--disable-webgl`; they never observed a render error and failed. Detailed pass3 evidence established that the actual model was mounted, so that flag did not establish the intended fault. Those results are retained and are not accepted as negative-path coverage.

Native pass4 on 2026-10-25 instead uses the actual canvas's `WEBGL_lose_context` extension. It observes real model drawing, loses its actual context, checks the localized desktop alert and unmounted body, then clicks the real retry control. The lost canvas is detached; a different canvas and actual Cubism model draw again. Eight checks passed with no unhandled page errors. Normal UI shutdown completed in 1061 ms with native exit 0; the input desktop stayed Default. Screenshots and the detailed report are retained at `output/execution-render-failure-native-20261025-pass4/`. No provider credential, fabricated context-loss event or synthetic life/health state was used. Actual unsupported-renderer construction remains covered by controlled component tests; this native acceptance specifically establishes context-loss recovery.
