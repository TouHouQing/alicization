# Agent 全链能力对照与实际验收

调研开始：2026-11-03；验收完成：2026-11-04。范围：Phase 1 桌面数字生命中的执行能力及其与记忆、人格、主动性、身体表达的连接。

本次继续上一轮 [完整生态调研与移植](2026-11-03-agent-ecosystem-integration.md)，增加当前上游变化核对、真实桌面任务和真实 Codex CLI 委派验收。这里区分三种证据：实际产品运行、受控集成/单元测试、上游源码/文档。没有把源码存在当作四个产品都在本机实测通过。

## 结论

Alicization 已具有自己的受约束 Agent 主链：接收当前请求 → 组装同一个人格与记忆上下文 → 按需发现能力 → 模型提出动作 → 权限与风险检查 → 持久化执行意图 → 实际执行 → 结算观察 → 核验结果 → 继续、修复或中止 → 回复 → 候选方法提取、独立复跑、批准、复用和撤销。

它不是“完整安装了 Pi 后就拥有 Pi 全部功能”。目前是复用和移植具体算法、工具语义及执行接口，同时保留 Alicization 的生命数据库、责任所有者和权限边界。真实 Codex CLI 是已集成的编码委派渠道，仍由原任务所有者跟踪，不能成为另一份人格或长期记忆。

本轮实际运行找到了两处业务断点，并修复：合法的工具流被误判为截断；已独立核验的文件结果没有完整进入回复事实链。另增加了规范操作的中文检索词，改善本地文件工具的发现。测试工具本身也修复了后台截图的 Inspector Promise 回收问题及取消命令只兼容 Unix 的问题。测试通过的范围及失败记录见后面的验收证据。

不能据此认定我们的通用编码、开放任务规划、跨工具泛化和长期内化已达到四个上游的同等水平。模型本身、模型的工具训练、服务端能力、默认工具组合和宿主环境都会影响结果，复制开源代码无法复制这些条件。

## 四个项目各自值得吸收的部分

### Codex

工具搜索按当前执行上下文构造可调用接口；调度器按工具是否支持并行选择共享或独占执行锁，并保持取消与执行追踪。值得吸收的是“发现、调度、权限、结果、上下文”共同作用，而非只复制循环。见 [工具搜索](https://github.com/openai/codex/blob/bfdbf01bfaeaa6ab23b10e2bd64ed031fd1e5619/codex-rs/core/src/tools/handlers/tool_search.rs)、[并行执行](https://github.com/openai/codex/blob/bfdbf01bfaeaa6ab23b10e2bd64ed031fd1e5619/codex-rs/core/src/tools/parallel.rs)、[安全模型](https://developers.openai.com/codex/security)。

优点是编码任务、工具调度、审批/沙箱和开发工具整合范围广。局限是这些能力不等于长期陪伴人格，也不能从开源 harness 推断闭源模型的规划质量。我们的一次真实长任务先超时后复测成功，不能用它得出任何整体胜率结论。

### Pi

稳定 coding CLI 的核心取向是小而可扩展，扩展、技能、模板、SDK/RPC 是主要增益入口。不能简单写成“Pi 没有子 Agent”：当前仓库的实验性 `pi-durable` 已支持持久任务图、归属子任务、提交后可见、崩溃恢复和取消屏障，API 明确可能变化。见 [主仓说明](https://github.com/earendil-works/pi)、[durable 文档](https://github.com/earendil-works/pi/blob/d71c66e05bdafd67e0558bfa65e748c71cd1f379/packages/durable/README.md)、[取消屏障测试](https://github.com/earendil-works/pi/blob/d71c66e05bdafd67e0558bfa65e748c71cd1f379/packages/durable/test/harness-cancellation-barrier.test.ts)、[用量账本](https://github.com/earendil-works/pi/blob/d71c66e05bdafd67e0558bfa65e748c71cd1f379/packages/durable/src/harness/usage.ts)。

优点是宿主可以组合所需能力，运行时、模型 API 和工具组件边界清楚；实验性 durable 层的“取消等待不等于取消工作”“父任务空闲须等子任务停止”很有参考价值。代价是宿主需要自己建立产品权限、记忆与结果标准，实验性模块还要承担 API 变更成本。Alicization 不适合同时运行另一套拥有独立人格、数据库和批准状态的 durable 根。

### DeepSeek Harness

持久化策略在模型请求发出、顶层工具派发之前等待检查点成功；超时策略把停止信号传给工具并等其返回，不通过超时竞争直接遗弃正在运行的副作用。PTC、MCP、LSP、目标轮驱动、后台任务由插件组合。见 [检查点实现](https://github.com/deepseek-ai/deepseek-harness/blob/8bd073392eef6f54e921a093b95076248eb08cbb/packages/session/session-checkpoint-policy/src/index.ts)、[超时策略](https://github.com/deepseek-ai/deepseek-harness/blob/8bd073392eef6f54e921a093b95076248eb08cbb/packages/guard/timeout-policy/src/index.ts)、[PTC](https://github.com/deepseek-ai/deepseek-harness/tree/8bd073392eef6f54e921a093b95076248eb08cbb/packages/workflow/workflow-ptc)。

优点是能力组合和运行边界明确，适合研究复杂执行系统。代价是插件依赖与状态所有权更复杂；官方仍标注 developer preview，不能把“模块多”解释为所有场景开箱可用。协作超时也依赖工具遵守停止协议，不能代替对失控进程的隔离和回收。

### Hermes

工具目录使用检索与按需加载减少全量接口注入；技能、跨会话检索、用户记忆、定时任务和委派共同形成长期使用闭环。当前委派模块还处理父来源、子任务权限与最终结果回收。每 Agent 的迭代预算分别计算，并不自动组成全树总预算。见 [工具目录](https://github.com/NousResearch/hermes-agent/blob/c314285f077e91937c995d419b9fa40af9eb4981/tools/tool_search_catalog.py)、[委派](https://github.com/NousResearch/hermes-agent/blob/c314285f077e91937c995d419b9fa40af9eb4981/tools/delegate_tool.py)、[预算](https://github.com/NousResearch/hermes-agent/blob/c314285f077e91937c995d419b9fa40af9eb4981/agent/iteration_budget.py)、[项目能力说明](https://github.com/NousResearch/hermes-agent)。

优点是长期工具使用、技能积累和自动化入口丰富。代价是更多运行面需要更多来源、权限、成本和调度管理。自主生成技能能提高便利性，但生成本身不证明跨输入可靠。我们保留“候选 → 独立复跑与反例 → 批准激活 → 使用后监测 → 降级/撤销”的门槛，便利性因此低于直接加载生成技能。

## 本轮业务修复

### 工具轮结束证据

真实供应商的结束块同时包含 `content: ""` 与 `finish_reason: "tool_calls"` 时，安装的 xsAI 0.4.3 记录了 step 结束原因，却没有发出 `finish` 事件。原主链因缺少事件拒绝发布提案。

现在只在流确实 EOF、尚未看到 finish 且有待发布提案时，读取最多等待一秒的 SDK settled step。要求只有一步、调用总数、顺序、ID、工具名完全一致，且有真实结束原因。缺少原因、截断、过滤、错批次、取消均不被当作成功；工具仍由生命执行器批准和执行，SDK 只拿提案桩。

实现：`agent-harness/provider-step-completion.ts` 与 `main-chat-stream-runner.ts`。真实本地 HTTP SSE 覆盖空文本结束、工具与结束合并、缺失、长度截断、内容过滤，另有取消和错身份反例。

### 独立验证后的文件反馈

实际编辑已成功，`closeLifeFileAction` 也已经独立回读并关闭 file goal，但回复审查只允许“读工具返回的内容”作为成功 outcome，导致真实字节长度等描述被拦截。

`life-file-effect-evidence.ts` 现在要求同一 effect 派生的 file goal、当前 card、同源 turn、已满足且独立的核验、路径/字节数/哈希逐项一致。写入文字只有完整 UTF-8 哈希和长度匹配才可作为文字证据；编辑/补丁还从同 turn 的实际完整读取与已批准参数重建结果，再与独立回读哈希比较。缺源、变更或未通过核验只能描述已有的操作状态，不能获得文字事实证明。复用既有文件变更投影函数，没有新增文件读取权限或第二份文件事实库。

这让结果反馈使用已经取得的证据，避免让用户看到“完成了写入，但不能确认最终内容”的错误保守答复。文学质量、其他文件和其他目标仍需各自的证据。

### 验收基础设施

后台截图只触发一次 native capture，以同步 Inspector 状态读取其最终值，避免 `awaitPromise` 被回收。测试窗口保持所有屏幕之外、不可获得焦点，仍核对原生进程正常退出与测试凭证清理。真实 CLI 取消目标改用 Windows/Unix 都能执行的 Node 等待命令，未降低取消 oracle。

### 中文能力发现

真实的“内容搜索后完整读取”任务原先使用六次主模型请求，其中包含额外的目录搜索往返。`capability-search-vocabulary.ts` 为规范文件/浏览器操作提供固定的中英文用途词，进入既有 Codex 相关性排序和 Hermes 检索；不索引历史用户值、失败输出或插件指令，不改变实际 schema、权限或风险。撤销的工具即便仍匹配中文词也不能被提供。

固定测试要求同一中文请求能同时发现本地内容搜索和全文读取。真实任务的请求数和实际回执另作记录；一次变好不被解释为跨任务的稳定成本收益。

三条跳过分别是：真实编码器写入方法、被动原生编辑器方法，以及单独的配置模型自动重规划用例。前两条没有在本轮运行；第三条的独立测试开关未开启。本轮另实际运行了三次**用户在产品界面修复步骤**，不能把它改称为无人工介入的模型自动修复。先前轮次的三次配置模型自动修复记录仍在上一份验证文档中。

实际学习测试为模型提供了明确的方法标识及参数要求，证明执行、迁移、复用与撤销连通；不证明在所有自然请求里都会自主选择正确方法。虚拟键鼠、任意外部网站、全部语言服务器及长期使用品质没有被本轮三条产品路径穷举。

首次真实运行中出现的协议误判、成功结果被拦截、截图采集异常，以及Codex首次长任务超时均被保留。修复后的三条产品路径使用同一个最终编译入口哈希核对，源码与产物信息见验证文件。

清理包含10份已经正常退出且移除凭证的测试资料目录，以及四份任务临时克隆的Git缓存。清理缓存前再次核对了260份保留源码的SHA-256；选定源码、许可证、清单、数据库和日志证据仍保留，应用仓库的Git元数据没有改动。

## 仍然存在的差距与开发顺序

1. **自然任务成功率和报告稳定性**：受控参数任务能验证连通性，却不能代表任意开放请求。应建立未知文件、含糊需求、改要求、工具撤回、网站变化、拒绝权限和错误恢复的固定任务集，保留所有尝试，统计成功率、假完成、假拒绝、重复副作用、接管率和总成本。
2. **全树资源与成本控制**：为主模型、压缩、检索、修复、编码委派统一预算和持久用量，区分已报告、估算和未知。不能把63动作上限写成外部编码器费用上限。
3. **受约束的并行执行**：按真实副作用和资源集合调度独立读；写入、桌面焦点和共享浏览器状态保持串行/独占。取消时等待所有在途工作停止，未知效果转核对。应以实际吞吐与重复副作用为验收，而非只增加 Promise.all。
4. **更完整的开发工具生态**：优先改善现有编码委派的上下文、诊断、交付和结果复核；再选择 LSP/PTC/扩展兼容的实际需求。引入上游运行时必须作为受约束的执行后端，不另建身份、记忆和批准真源。
5. **方法的长期泛化与目录性能**：1000容量测试是存储测试。还需真实学习来源的大库延迟、中文自然选择、跨目录/网页变化、回归评估和撤销后不可复活的长期验证。旧不可变页的审计保留与可逆清理也需明确政策。
6. **供应商与缓存覆盖**：当前诊断只反映供应商报告的用量；未实现所有专属缓存指令、原生模型协议和费用面板。模型和接口必须独立固定，避免把换模型的收益算作 harness 收益。
7. **长期数字生命质量**：保持同一人格、关系、记忆和身体表达；用持续使用观察主动性噪声、任务干扰和陪伴质量。不能通过加工具或加动作数量直接宣布“数字生命已完成”。

后续顺序应优先稳定真实任务闭环、统一预算和安全并行，再扩大工具生态。所有开发继续沿用同一个生命状态写入者、证据撤回和中断策略。
