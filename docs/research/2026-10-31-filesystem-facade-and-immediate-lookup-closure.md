# 文件操作、即时查阅与受理回复：实现和验收范围

本轮继续 Phase 1 的桌面生命闭环：实际行动、独立核对、可恢复的文件版本和诚实回复共用同一人格与责任记录。EX00–EX23 的完整验收仍未完成；本报告不把局部测试、计划受理或原生子进程退出当作根目标完成。

## 修复内容

主对话文件门面与底层原生工具原先存在参数形状差异。搜索补充默认值、目录增加 recursive、文件读取移除显示预算后，精确授权门会拒绝实际调用。现在只有可信主进程读门面可以使用固定投影：持久效果保留原始模型参数，执行门从不可变副本计算实际原生参数。直接原生任务继续使用精确参数。内层异步作用域与父级共享关闭标记，不能在对话取消或结束后继续执行。

普通写入原先丢失 expectedHash；编辑与补丁虽然完成字符串计算，却在原生写入处被当作不同能力拒绝。现在它们把真实读取快照与原始指令交给同一执行门重新计算目标字节，并把快照 SHA-256 传到底层文件句柄核验。路径、内容、源版本、责任、租约和取消检查均保留。替换文本按字面量处理，美元符号和 CRLF 不会被 JavaScript 替换语义改写。

编辑、补丁和直接写入使用同一加密版本仓库及恢复控制。原始字节在变更前保存，恢复需要原对象和当前内容仍匹配；它不重新证明原任务成功。尚未核对的编辑/补丁即使只留下预日志密文，也受活动效果保护，不能被孤立文件清理删除。试运行只生成预览，不落盘，不创建虚假的写入或恢复记录。

文件显示截断把提示语计算在返回预算内，并在完整 UTF-8 边界结束。完整源文件的字节数、哈希和显示内容长度仍有不同含义。

实际自然语言查阅还复现了模型为未知文件猜测静态产物路径、改建后台计划，以及受理回复被真实性校验拦截的问题。现在主对话在同时具备真实搜索和读取后端时，为明确、即时的只读搜索与完整读取请求选择直接工具。含持久计划、监控、稍后处理、修改或显式计划工具要求的请求保留规划入口；模糊请求也保留原路径。此选择不授予额外文件权限。Windows 产物契约同时拒绝包含非法文件名字符的占位路径，且拒绝前不创建任务。

受理措辞中的搜索、读取可以只是任务名。只有实际同时包含搜索、读取并且完全只读的当前计划能够绑定这类受理回复。执行完成、额外上传、修改以及其他计划仍需各自证据。这里的修复不把受理变成完成，也不取消语义审查。
