# 原生菜单、窗口连续性与恢复执行

本轮改动继续沿用桌面 LifeTurn、WorkPlan、Effect、风险许可和独立验收。没有增加第二套执行器、目标状态或人格状态。

## 实际发现

真实 WPF 控件树会同时暴露菜单控件和同名文字节点。旧绑定只比较名称，把这种正常界面误判为歧义。现在使用已接受操作中明确指定的角色过滤同一次已提交的原生观察，再要求唯一匹配；同角色重复、缺失角色、错误来源和浏览器观察仍被拒绝。

修复匹配后，后台实测发现 WPF 的 Expand 调用可能激活带有 NOACTIVATE 样式的窗口。自有测试窗口立即记录并关闭，原始失败报告保留。生产 worker 现在在菜单或下拉控件的任何模式调用之前检查实际前台范围，不主动获取焦点；不满足条件时返回 FOREGROUND_REQUIRED、requiresForeground=true、effectMayHaveOccurred=false 和 sideEffectState=none。派发之后失去条件时保留未知效果，不能冒充未执行。

## 显式继续的闭环

已知菜单拒绝会使原控件观察失效。主界面的显式继续命令现在只为已结算且明确没有派发效果的前台拒绝生成新的计划修订，插入新的只读观察，并把未完成操作重新绑定到该观察。

新观察同时绑定原观察步骤，核对 HWND、PID、进程启动时间、窗口类、桌面、标题和可空 GW_OWNER。焦点及位置可以正常变化。任一身份不同，新的只读结果记为失败，依赖的操作不会派发。此前已完成的写入、输入及其回执原样保留，不重放。

刷新、计划修订和反馈来源在同一事务中提交。请求标识检查参数哈希；重复提交不会再建一轮操作。未知效果先核对，过时修订、角色不匹配、取消或撤销的责任不能借继续命令恢复。

## 任务页面与对话的原因一致性

后续复核发现任务页面只显示阻塞状态，缺少前台不足的处理说明。新增 `execution-work-blocker` 从同一活动人格、根责任、契约、计划修订、输入哈希、attempt、操作和已提交回执投影原因，任务页面与对话确认共用该投影。未知效果要求先核对；窗口身份变化或没有可恢复的原观察时，说明需要重新指定未完成操作，并停止提供无效的继续入口。

有原窗口观察的名称直写计划和文字输入，现在也能在已知未派发拒绝后重新观察。连续刷新只沿已有窗口身份链前进；两个互不关联的窗口观察仍视为歧义。不会因为缺少绑定而猜测新窗口。

工作副本 `output/execution-v329-native-blocker-green-20261101-pass2.json`：61 项通过、0 失败、0 跳过，包含真实 WPF 绑定与名称直写的各三轮拒绝、正常恢复、文字输入恢复、原因投影隔离和实际 Vue 模板的提示/按钮状态。桌面 Node/Vue 类型检查通过。它与前述 62 项有重叠，不相加。

成品体验还新增三轮真实模型原生菜单任务、可见提示、主界面继续和取消检查。退出后的专用只读检查器要求菜单拒绝与新的观察真实存在于对应计划，且方法十类评估、四次独立文件验收和撤销状态持久化；没有沿用普通文件方法的错误体验格式。新成品实际执行结果尚待后续报告。

## 下拉选项读取、焦点与确认范围

后续真实 WPF 下拉框反例表明：即使不展开，`SelectionItem.Select` 仍可能激活窗口。原始失败 `worktree:output/execution-v330-passive-select-20261101-pass1.json` 保留独立选择事件与前台检测记录。输入桌面上的选择现在要求原窗口已经在实际前台，不能自行取得焦点；非输入桌面的测试正向选择不能算作输入桌面的正向验收。

闭合下拉框通过 `ItemContainerPattern.FindItemByProperty` 读取逻辑选项，不展开、滚动或调用 Realize。该语义核对了 [.NET API](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.itemcontainerpattern.finditembyproperty?view=windowsdesktop-10.0) 与 [WPF 实现](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Automation/Peers/ItemsControlAutomationPeer.cs)。没有复制第三方源码。

选项超过 64 个时，观察返回前 64 个和 `optionsComplete=false`，其他控件仍能正常读取；选择操作继续拒绝不完整枚举。原有窗口、进程、选项来源、旧选中值、过期许可与未知效果边界保持适用。风险操作的效果摘要和最终原生派发同时绑定输入框与选择框，因此确认之后收件人或账户变化会使操作失效。

新后台夹具用真实 WPF 窗口独立记录选择、下拉展开、菜单点击和前台变化，正常退出后校验原生 Job 进程树停止。当前源码的定向、完整和成品验证使用不同报告，不把先前后台拒绝或旧版本通过记录替换成新的正向结果。

## 全量回归中的临时目录问题

`output/execution-v329-full-main-20261101-pass2.json` 保留 6566 项通过、29 项失败、25 项跳过。临时目录位于仓库的 `type:module` 范围内，使测试生成的无扩展名 CommonJS 训练脚本按 ESM 启动；较深的临时路径也影响原生进程夹具。本轮把专属测试临时根移到仓库外，再运行原断言，不修改全局 Node 配置。原生进程失败的归因仍以新回归结果为准。

另一个独立产品问题是列表摘要把任意路径祖先中的 Desktop 当作当前列举桌面；改为核对目标目录本身。回归特意在 `Desktop/project` 内生成真实目录，仍要求普通列表摘要和 Unicode 名称解码正确。

工作副本最终定向报告 `output/execution-v330-final-related-20261101-pass3.json`：210 项通过、0 失败、1 项平台跳过；跳过项仅为 POSIX 进程组，Windows 原生 Job 的 CLI/Codex/Claude 崩溃恢复按原三轮矩阵实际执行。桌面 Node/Vue 类型检查通过。`output/execution-v330-wpf-qualified-three-20261101-pass2.json` 记录当前 worker 三轮真实选择、滚动和确认期间选中值变化拒绝。`output/execution-v330-native-compiler-path-20261101.json` 是相同固定源码的纯编译长短路径对照，未启动执行目标。主目录新一轮全量及精确新包体验仍待独立结果。

## 继续入口与原生停止检查的后续修复

产品复核发现“切到目标窗口后再点继续”会造成误导：点击设置窗口可能重新改变前台。前台不足且有有效原窗口观察的按钮现在显示“重新检查窗口”，说明会核对原窗口、条件满足才继续未完成操作，否则保持暂停。没有原目标及未知结果时仍禁止此入口。新按钮沿用同一个主进程命令，不增加取得焦点或绕过系统限制的通道。工作副本 55 项关联检查通过，实际编译模板的点击核对同一人格、计划、修订与单次请求；成品检查增加新文案及按钮断言，原来的三轮拒绝、重新观察、取消和独立效果检查保留。

v330 全量报告 `output/execution-v330-full-main-20261101-pass2.json` 为 6596 项通过、4 项失败、25 项跳过。三项备份压力场景遇到保留空间保护；另一项是测试检查器的真实竞态：CIM 返回后进程退出，再通过 PID 打开进程时抛错。原结果保留。

检查器先通过 OpenProcess 持有原生句柄，再读取 CIM、映像和创建时间；查询退出及停止均使用同一原生句柄，避免重新打开已复用的 PID。仅原生 API 的“PID 不存在”返回可直接判为结束；权限和身份不匹配继续拒绝。实际旧/新对照在 CIM 查询后停止两个自有进程，旧检查器失败、新检查器正确确认停止，记录 `worktree:output/execution-v331-native-inspector-race-20261101.json`。

原 CLI/Codex/Claude 四个崩溃时点各三轮通过（12 个用例、36 轮）；另两项实际进程回归验证错误映像、nonce、创建时间不能停止存活进程，以及确定发生在 CIM 观察之后的退出。两项新增检查与原矩阵分别记录，未把被过滤用例计为再次执行。新的完整回归在 D 盘自有临时根执行，仍要求 1001 份独立普通文件副本、原保留空间及实际还原重开，不复用或改名先前失败报告。

本轮归档 99 个已结束单元备份目录及旧版本 47 个无链接子目录，共 3027 文件、638943937 字节，迁移后逐文件哈希核对；原处保留含链接、WAL、锁或较新内容的目录。另有 512 个旧测试文本文件无损压缩，哈希无变化。当前运行目录和此前被策略拒绝的路径未参与归档。完整清单保留于实施清单的新检查点。
