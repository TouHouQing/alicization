# Phase 1 真实生活链路补齐

目标是同一位长期存在的她：陪伴与行动共用人格、记忆、情绪和责任。此次从实际版本的 11 回合体验中确认的断点出发，继续实现与验收；不以新增模块数量、合成状态注入或模型说自己做到了作为完成依据。

## 参考实现与取舍

固定版本、源码路径和文件哈希沿用 `2026-10-05-desktop-life-source-manifest.json` 与 `2026-10-06-interaction-intent-source-manifest.json`，累计 13 个开源项目。以下是本轮实际改动所依赖的实现结论，而不是对产品营销描述的复述。

| 项目 | 参考的实现节点 | 本项目采用的约束 |
|---|---|---|
| Pi | `core/tools/write.ts` 与 `file-mutation-queue.ts`：同文件队列、可替换 I/O、await 后检查取消 | 在现有安全漏斗后提供默认本地文件实现；队列直接按 MIT 改写复用，新增批准后的内容前置条件、字节核验和容量限制 |
| Hermes | `agent/session_persistence.py`：持久化标识绑定内容、内部恢复消息不冒充用户 | 已验证回复由主进程持久化；前端消费结算回执，避免重复写入与恢复步骤污染人格材料 |
| N.E.K.O. | `static/vrm/motion/player.js`：基础姿态与瞬时动作分层、低姿态保留、淡入淡出与结束恢复 | 身体层移除自己的偏移后才执行下一动画帧；语音层不能覆盖长期姿态或留下累计旋转 |
| TalkingHead | 发音与头手动作时间轴、已有 MIT 过渡曲线 | 继续使用已固定并署名的过渡函数；新细动作读取真实播放段、能量和语句重音，等待与取消不继续说话动作 |
| Motion Engine | 动作轨道、播放结果与取消恢复 | 测试实际骨骼变化及恢复，而非只验证动作名称出现 |
| Open-LLM-VTuber | `single_conversation.py`：对白、语音、表情与中断的同一轮生命周期 | 保持一个回合来源，已验证可见回复、脚本与音频段共同归属；后台测试静音但检查真实播放回执 |
| SillyTavern | expressions 扩展中的模型能力、标签和回退 | 配置别名须匹配模型实际支持项；未知首别名不吞掉可用标准表情 |
| Generative Agents | `cognitive_modules/plan.py`：目标、计划、反思和行动之间的连续性 | 个人项目须形成可持久化责任、真实产物、独立证明和后续反馈；不复制虚构世界中的观察当真实桌面经历 |
| Graphiti | `edges.py`：事实关系与有效时间 | 跨会话回忆读取当前有效版本；纠正、撤回和过期会改变下次检索，不能只保留旧会话文本 |
| Letta Code | `memory-worker.ts`：记忆工作与主回复的分工 | 记忆处理有证据、预算及结算；记忆工作不生成另一位人格或代替当轮可见回复 |
| OpenHands SDK | `conversation/event_store.py`：事件持久化与执行结果 | 执行动作、工具结果、目标满足与呈现完成分开记录；失败、取消、重启必须可追踪 |
| LangGraph.js | SQLite checkpoint 与恢复 | 重启接续使用已提交版本和实际未完成责任；检查点本身不能证明行动已完成 |
| VPet | `MainDisplay.cs`：常驻状态与动作衔接 | 常驻表现需要倾听、休息、转换与恢复；不靠随机更换动画伪装主动生活 |

闭源产品仅参考公开协议，不声称取得其内部实现：

- [Convai Agentic Actions](https://docs.convai.com/api-docs/convai-playground/character-customization/agentic-actions) 明确区分模型发出、协议解析、客户端执行和结果观察。这对应本项目的动作接受、执行回执、独立目标核验与实际身体采样。旧 Action API 已标注迁移，不把旧文档当新实现模板。
- [Inworld Realtime](https://docs.inworld.ai/realtime/overview) 将交接、打断、音频输出和终止放在同一会话协议。采用其生命周期原则，保持本地人格所有权，继续使用当前用户已经配置的供应商。
- [Amica](https://github.com/semperai/amica) 作为 VRM、语音与情绪组合的公开参考。此次两次 Git 拉取网络失败；未将其未检查代码记为复制来源，其模型与图片资源也没有导入。

## 本轮闭环与验收要求

| 方面 | 所有者和实现边界 | 必须实际证明 |
|---|---|---|
| 人格、关系连续性 | 既有人格／关系所有者；操作拒绝只改变该操作状态 | 保留自己的选择，纠正后能解释变化；拒绝文件权限不产生“不信任她”的臆测 |
| 当下心智意图 | 当前意识帧、当轮规划与回复；空的回复指令不等于无意图 | 普通无视觉输入也有带 cardId、turnId、来源和有效期的意图，provider 与身体使用同一轮 |
| 对话与失败恢复 | 主进程 provider 结算与提交是权威；原始输出与可接受投影分别保留 | 可读原文不被前端第二次格式判定误拦；技术故障有恢复状态，用户回合只出现一次 |
| 日常执行 | 已注册能力、现有风险漏斗、默认本地读写、当前责任与结果 | 无 filesystem 服务也能创建并读回指定 QA 文件；问结果不擅自重写；真实失败不能报完成 |
| 风险、暂停与取消 | 路径规范化、私密黑名单、创建／覆盖差异、内容前置条件 | 普通工作区新文件可直接创建；覆盖或外部路径仍有明确范围；批准后文件变化拒绝旧写入 |
| 确认 UI | 主进程结算事件；专用 Vue 队列负责显示、到期与 scope 清理 | 确认不挡聊天；到期、取消、切角色、退出都收尾；旧 RPC 结束不关闭后一条请求 |
| 表情 | 共享情绪、模型实际表达能力、别名候选与强度 | 未绑定的别名跳过；真实模型表情权重与画面符合当轮表达，不只看日志标签 |
| 动作、肢体与语音 | 底层姿态、已有瞬时动作、真实语音身体层 | 头颈、胸背、手腕与可用手指跟实际语音段运动；停止后恢复，连续播放无旋转累积 |
| 主动性与个人生活 | 同一 initiative、motivation、personal-project 所有者 | 自主兴趣有计划、可见产物、核验、后续发展；忙碌与安静边界有效，不用计时消息充数 |
| 思绪与反思 | 现有 cognition、inquiry、reflection 与证据依赖 | 问题经过证据与修正影响下一次选择；没有新证据时不编造“思考结果” |
| 长期记忆与成长 | 可版本化事实、经历、回忆计划、项目反馈与清理 | 新会话与重启仍可检索；纠正旧偏好、真实作品反馈影响后续；加速跨日测试与真实长期陪伴分开报告 |
| 发行与实际体验 | 固定源码、编译结果、包内字节、独立 Windows desktop | 最终新 EXE、原生库、真实发送和实际身体均验收；输入桌面保持 Default，无音频打扰 |
