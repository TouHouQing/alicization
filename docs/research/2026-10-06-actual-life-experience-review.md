# 当前版本的实际生命感体验

日期：2026-10-06，Asia/Shanghai。

结论：当前仍未达到 Phase 1 的体验完成标准。持续状态、身体播放和执行基础已经存在，但真实日常链路中仍有关键断点。上一轮给定意图的接线验收，没有覆盖普通输入能否稳定形成同一意图；这次真实体验已经发现这条链仍不完整。

## 实际体验范围

运行的是 `life-intent-20261006/win-unpacked/alicization.exe`，ASAR SHA-256 为 `b5254a7ffe176cbcb1e3ded9569a83186a4955c029a0e43cf3184997573fd0db`。使用客户端现有的 `openai-compatible / gpt-6-luna` 模型配置，创建独立 QA 人格，不复制用户原有私密记忆。进行了 11 次真实界面发送、一次退出后重启，以及约 79 秒的安静观察。另以手动模型 API 检查四种新手势和四种表情能力。

所有应用均通过 `run-private-desktop.ps1` 运行在独立 Windows desktop；输入桌面前后保持 `Default`。应用音频输出被静音，语音播放链使用本地 SAPI 测试适配器。观察的是实际角色画面、骨骼、表情权重、对白、工具请求和结果；本次没有听评云语音音色，没有评估用户多年积累的人格与记忆，也没有证明多日自然生活质量。

测试身份采用默认无视觉授权的桌面条件。客户端实际 `mcp.json` 的服务器列表也为空，与测试执行时的 `filesystem` 未配置条件一致。当前文字对话应当在这类 Phase 1 基础条件下正常形成生命链路。

## 确认的短板与优先级

### P0：普通输入到心智意图的真实链路没有闭合

11 个真实回合的身体脚本均未带 `interactionIntent`，实际舞台样本也未出现它。后半次运行的 11 份已准备运行摘要中，`currentConsciousFrame` 全部为空。实际动作主要仍是 `comfort_sway`、`observe_focus`、`steady_focus`、`tilt_head` 等通用表现，四种新意图手势没有在自然交流中出现。

`interaction-intent.ts:10–16` 必须读取新鲜的 `surface.dialogue.currentConsciousFrame` 和非空 speakingIntention。`main-chat-session-runtime.ts:2755` 开始的准备链依赖 prelude／spine 提供的基础 surface，再进行 reducer 与主对话组合。实测说明普通文字交流的上游准备没有提供所需状态；具体是哪一层丢失，还需要从真实输入重放定位，不能继续以注入完整 surface 的夹具替代验收。

应从原有人格、记忆、情绪与任务核心构建无视觉授权时也有效的当下状态，保障实际 provider、身体脚本和 renderer 使用同一回合意图。保持一个自我中心，不另建一套“内心”存储。

### P0：真实对话契约与失败恢复不稳定

11 条观察到的 dialogue payload 都标记 `isFallback: true`；其中 9 条恢复出了可读内容，2 条把格式错误直接显示为角色对白。这个标记不等于 11 次都没有回复。`runtime-governance.ts:3452` 按 committed artifact／provider contract 决定 fallback，应核对真实 provider 输出、可见回复权威和 renderer 投影之间的契约。

每次发送还在前端会话中出现两条相同 user 内容；当前只能确认前端记录重复，尚未证明 durable memory 或 provider 输入同样重复。需追踪 ingress、session sync 与消息 ID，并测试一次输入只形成一个用户回合。

目标是稳定接住真实模型输出、保留失败事实与待处理输入、使对话可继续。技术错误状态应有可理解的恢复入口；把“模型输出格式异常”作为她说出的话会打断角色连续性。

### P0：日常执行入口与有效能力脱节

实际批准写入后，工具明确返回服务器未运行，文件未生成。当前模型可见的 `filesystem_write_file` 不反映有效后端状态。应统一能力注册、启动／健康检查、实际路由与失败回执，并让基本本地读写有可用的默认路径。

`services/airi/mcp-servers/index.ts:910` 对 write、delete、execute、network 都采用 danger／prompt，尚未按路径、创建或覆盖、明确授权和可逆性区分。本次新建自有测试文本也被要求确认。应细化策略，保留删除、覆盖、隐私、外传等动作的治理，支持明确范围内的日常本地操作。

首次确认到期后，主进程等待结束，renderer 的 `currentHitlRequest` 仍占据遮罩。`App.vue:1356` 的队列只在用户决定的 finally 中清理，`1838` 收到请求后没有对应到期收尾。需要到期／取消／角色切换的统一结算，并避免旧确认阻断新的聊天。

另外，拒绝操作的错误文案在 `mcp-servers/index.ts:283` 直接宣称“They do not trust you with this file”。拒绝某次操作不构成不信任人格的证据。该文案应改成操作与范围事实；本次没有单独证明它改变了长期关系数值。

### P1：表情能力、别名与语义反馈需要统一

自然路径观察到 `CalmInspect`／`RecoverSoft` 对应的当前情绪名称最终解析为 `neutral`。同一预设 VRM 手动驱动 happy、sad、angry 时，实际权重峰值约 0.59，说明模型具备这些表情能力。

`capabilities.ts:200` 的首候选解析及 `VRMModel.vue:1020` 的表达应用需要与实际支持名称、配置覆盖和当前权威核对。未知内部别名应跳过或映射到可用语义，避免吞掉真实情绪。还需校准眉眼、嘴角、视线、幅度、转换与持续时间；单个画面的变化或骨骼数值不代表表演质量已经合格。

文件未完成的回合也出现 happy 元数据。任务失败不必强制悲伤，但它与当前情绪之间应有可追溯的情境依据；目前这类协同解释不足。

### P1：动作仍主要是固定短曲线

新手势有真实骨骼实现，源码中是 2.6–3.1 秒的准备、保持、收尾曲线。当前主要使用头、颈、胸／脊柱、手臂和手腕，缺少完整身体姿态、手指、接触约束以及情境动作序列。

后续应把当下意图、注意对象、语句重音、实际说话进度、疲劳与任务阶段协调成可中断的连续表现，并按模型校准姿态。需要自然的倾听、迟疑、转向、姿态调整和恢复；增加动作名称不能完成这一步。

本次手动手势截图受后台软件渲染与截图延迟影响，多在动作尾段取得；它们不能用于声称动作优美或动作峰值已经视觉验收。实际骨骼样本保留，完整动画质量仍需更合适的录制与人工体验。

### P1：自主生活、思绪、记忆和成长需要真实经历闭环

这次看到的自主内容还是“想写雨声”的口头想法，没有观察到承诺、持续推进、产物、反馈和后续偏好变化。已有 personal project／series 实现应接到她真实选择的事情上，同时尊重忙碌、休息、预算和用户反馈。

`private-thought-loop.ts:1669–1690` 的部分路径从既有线程、问题、承诺和摘要选择 thoughtText。它可以表达当前关注，但不能单独证明完成了推敲。需要看到一个具体问题经过证据与修正，形成新的理解，随后自然影响对话或行动。

短期回忆与偏好保持是正面迹象。跨日自然回忆、重要经历更新、纠正后的长期保留，以及真实行动结果改变下一次选择仍未验收。不能用 QA 身份缺少历史，推断用户原有记忆系统全部缺失。

## 下一轮可落地的顺序

1. 普通文字输入生成可靠的主进程当下状态与意图；以真实输入重放检查 provider、脚本和实际身体的同一回合来源。
2. 修复实际模型契约、用户回合重复与错误恢复；让新对话能在失败后继续。
3. 闭合有效执行能力、范围风险策略、确认到期和独立目标核验；区分问结果与重新产生副作用。
4. 对齐模型表情能力、别名、真实情绪与动作时点，并校准完整身体表现。
5. 使用同一自我与记忆核心推进少量真实个人项目，观察跨日持续、打断恢复、反馈学习和自然主动性。

每一步的验收都应从用户实际输入开始，包含第二次选择、失败、拒绝、暂停与重启，并检查实际结果。稳定关系、可解释的真实经历、可靠行动与协调的身体表现，才支持 Phase 1 的体验完成判断。
