# Live2D 产品体验与缺陷检查

本轮从新建人格、连接对话服务开始，全程使用 Live2D，依次检查角色、设置、模型目录、记忆、主动节律、备份、服务配置、托盘窗口、实际对话和数据导入导出。GUI 运行于独立 Windows 桌面；输入桌面始终保持 Default，截图只来自本轮自己的应用窗口。

当前工作以 Phase 1 的同一人格、同一情绪和同一身体状态为约束。持久的待机偏好、临时动作预览、实际 SDK 播放和加载资源分别有明确归属；修改不改变主进程的人格、记忆或执行权限语义。

## 发现与修复

| 问题 | 原因与修复 | 验证方式 |
| --- | --- | --- |
| 单只眼睛重置后闭眼 | 两个重置按钮写入 0；改为对应的睁眼默认值 1 | 实际滑块、重置按钮及持久参数读回 |
| 部分滑块没有名称，禁用状态不生效 | FieldRange 未关联可见标签，Range 未将 disabled 传给原生 input；补齐关联和属性传递，并保留明确的零上限 | 原生控件 SSR、实际键盘操作 |
| 预览与参数操作区域混在一起 | Live2D 场景按整个窗口尺寸建立画布；改为自己的容器尺寸，并分开预览与滚动表单 | 宽窄原生窗口、画布和表单的实际几何 |
| 窄窗口的帧率标题逐字换行 | 帧率选项占满横排且禁止收缩；改为标题、说明和选项上下排列 | 实际设置为 30 FPS，读回渲染器限制；标题高度为单行并核对截图 |
| 点击提取主题颜色没有结果 | 页面没有绑定用于取色的画布；改为捕获已加载模型的实际画布，加入忙碌状态、错误提示和模型变更检查 | 实际按钮、真实颜色选项、截图 |
| 待机选择串到其他模型，打开设置改变自动待机 | 旧选择保存为全局键，初始化又自动选第一项；改为按模型保存，保留默认自动模式 | Pro／Free 切换、设置重载、自动模式恢复 |
| 选了待机动作却没有播放 | SDK 随机待机抢先占用同等优先级，拒绝结果被记录成成功；在 SDK 待机入口采用已解析偏好，未启动请求保持 deferred | SDK 的实际 motionStart 状态与动作索引 |
| 一次预览不能可靠重放，影响持久状态 | 预览与待机共用持久 currentMotion；改为有独立请求 ID 的模型范围内临时消息，使用前景播放优先级 | 重复请求、模型范围、状态不被改写、实际 Cubism 播放 |
| 关闭待机可能打断当前动作 | 根据动作组名判断待机，并直接停止所有动作；改为根据实际 SDK 优先级处理，保留前景动作 | 前景预览期间切换待机，观察真实优先级和动作 |
| 透明区域可能捕获输入，偏移预览的鼠标追踪不准 | 使用较大的模型矩形判断命中，且客户端坐标未换算到画布；改为画布坐标换算和实际 alpha 命中 | 透明边缘、空白点、人物像素、拖动及滚轮 |
| 无效模型或保存失败仍能进入目录 | 预览错误被吞掉，列表先更新再等待写入；改为有效预览和 IndexedDB 成功后发布，失败显示提示 | 损坏 ZIP、存储故障、等待写入、目录数量 |
| 写入超时后可能出现残留模型 | 超时无法取消 IndexedDB 事务；迟到的提交只回滚该次新建且尚未发布的记录 | 虚拟时钟触发超时、迟到提交、原有记录保留 |
| 大写 ZIP 放行后 SDK 仍拒绝 | 底层只识别小写后缀；仅向 SDK 提交的 File 规范化后缀，保留目录中的原文件名 | 大写 ZIP 实际导入、改名、重载和绘制 |
| 改名没有保存，重载又恢复文件名 | Editable 没有提交处理，重载使用了 file.name；连接保存处理并恢复持久 name | 改名后重载目录和实际模型选择 |
| 预设模型的“移除”容易误导 | 预设会在重载时重新出现；预设只展示名称，文件模型保留操作入口 | 预设和用户模型的实际菜单 |
| 加载失败留下不可见画布，缩略图开销过大 | 隐藏画布仍可命中，异常路径未可靠释放；加入 pointer-events:none 和完整释放，将绘图缓冲降至 768 × 1024 | GPU 构造失败、无效模型、析构失败、DOM 与绘图尺寸 |
| 预览关闭或切换模型时偶发空白 | 当前 SDK 对 ZIP 使用相同资源索引；为每个实例分配独立资源归属，异步完成后再次检查画布、来源和模型归属 | 同文件并发归属、导航取消、实际导入与模型切换 |
| 本机模型首次显示后重载又失败 | 对照中直接 Blob 读取三次失败，四次 ArrayBuffer 读取均完整；本机 ZIP 经 SDK 可取消的字节读取后，以内存 File 解码 | 同文件、同窗口与预览窗口的成对读取及实际重载 |
| 已撤销旧来源仍被报告为当前加载错误 | 来源失效后的 fetch 失败被当成现有模型失败；释放旧请求并按取消处理 | 延迟成功、延迟失败及实际快速切换 |
| 无配置 JSON 的压缩包不能使用默认待机 | 推断的动作组为空，SDK 默认寻找 Idle；推断动作采用 Idle 组 | 用公开 Free 模型移除配置 JSON 后实际导入 |
| 桌面图标缺少可读名称 | 控件没有 aria-label／title；使用已有翻译给操作命名 | 实际控件名称和截图 |
| 后台验收的退出检查偶发超时 | 日志采用单一文件描述符、顺序写入及关闭前排空；测试工具在异步退出完成前保持 Node 调试连接 | 真实文件系统 1,000 条写入；同一安装包的完整正常退出，以及无 Node inspector 的原生关闭按钮 |

旧的全局待机选择只迁移到其已知活动模型，并删除四个旧键。迁移不会把同一选择赋给其他模型；重置清空所有手动待机偏好。模型可用动作仍是保存偏好的校验依据。

当前整组针对性测试为 24 个文件、302 项，全部通过。覆盖模型导入与存储、资源与加载归属、运动与表情投射、SDK 优先级、界面原生属性、日志关闭、人格与情绪连续性、主动性约束和执行风险。完整工作区 typecheck 通过；lint:fix 无错误，仍有 725 条 ESLint 警告和 7 条 Oxc 警告。

dev13 编译版完整使用流程通过：109 个界面状态观察记录、225 项检查、无页面异常，完成实际模型对话和聊天数据导入导出，正常退出用时 937 毫秒。最终发行包随后独立通过同样的完整流程：109 个观察记录、225 项检查，正常退出用时 1,078 毫秒、退出码 0。所有观察中的已选择渲染器均为 Live2D，无未解析翻译键和意外 Live2D 加载异常；QA 凭据已清除。

同一发行包另行通过不带 Node inspector 的原生启动检查：私有桌面窗口归属由 Windows 枚举实际验证；读取实际 Cubism 像素后，通过软件自己的“关闭”按钮退出，用时 1,058 毫秒、退出码 0。该项仍使用渲染器 CDP 和软件 GL，未向 Default 桌面注入鼠标或键盘事件。

## 仍有使用限制

- 私有桌面的软件 GL 与截图不能证明 Default 桌面的物理点击、实际显卡、游戏覆盖和多显示器表现；本轮保持用户桌面可用。
- 所有服务配置入口都可以检查，所有供应商的真实连接、OAuth 和付费服务仍需要对应账号。单个实际模型成功不代表所有供应商成功。
- 真实麦克风、声音听感及完整语音对话没有在本轮硬件环境中验证。
- 本轮实际创建了生命备份并显示恢复入口，未操作恢复后的重启流程；真实电脑执行的完整操作场景也未在此轮 UI 检查中重跑。执行策略与生命运行时的单元检查不等于这些实际场景通过。
- 高级记忆、训练、能力审计与动作映射页面仍有较高说明密度；页面能打开不等于普通用户无需学习就能使用。
- 标注 WIP 的视觉、游戏及外部集成页面仍应按其实际状态理解。短场景不能代替长期陪伴和自然主动性的持续使用证据。
