# Windows 桌面启动与大历史恢复修复

目标：保留同一个角色、记忆和会话，让已有大量本地记录的安装版也能正常显示 Live2D 人物和桌面按钮。

## 原因与修复

现有配置副本的 IndexedDB 保存了 10,071 条聊天记录。旧的 `canonicalizeSessionMessages` 对每条消息扫描已经整理的全部消息，多次恢复时重复执行，阻塞渲染线程。全新配置与仅复制 Local Storage 的启动可以成功；复制 IndexedDB 的启动会失去响应，原生截图停留在资源准备阶段。

历史整理改为使用稳定回合标识、文本和时间范围建立索引。稳定回合与旧式消息分别索引，保留原来最早匹配的语义；合并后重新登记身份，避免较丰富的重放消息更改内容后留下旧索引。相同文字但属于不同回合的消息仍分别保留。中断前缀、工具结算和语音交付记录继续按既有规则合并。

同时修复无时间戳、标识重复的旧式上下文记录在多窗口恢复时反复追加的问题。对完整相同的缓存项按已有出现次数匹配重放副本，保留持久快照中的每一条记录以及超出快照数量的新记录，不凭借重复标识直接删掉不同内容。

Windows 原生透明表面分别在桌面控件挂载和人物挂载时各绑定一次，避免模型等待使全部入口不可见。绑定使用 `showInactive`，不会重开用户主动隐藏的窗口，也不会在悬停时反复触发。

内置模型直接读取当前版本的资源 URL，不再等待导入目录的 IndexedDB 遍历，也不接受过期数据库记录覆盖内置资源路径。导入模型继续从本地目录读取。

## 验收

- 定向单元测试覆盖 10,071 条旧式消息、10,000 条相同文本的独立回合、时间范围边界、替换后的索引、内置模型与目录等待、Windows 两阶段表面绑定。
- 产品验收必须启动实际打包的 exe，分别使用全新配置和已有配置的副本；确认人物像素、屏幕内按钮、历史记录、设置入口与正常退出。
- QA 在独立 Windows desktop 上运行，声音静音，不切换用户输入桌面；仅清理本次复制的配置目录，原始角色、记忆和聊天数据保持原样。
- 全仓类型检查和 lint，以及相关聊天、交付、启动回归测试均须通过。
