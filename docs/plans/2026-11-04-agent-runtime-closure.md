# 四个上游项目的运行层整合与验收

目标：增强 Phase 1 的执行能力，同时沿用唯一人格、记忆、责任、风险准入和身体状态；上游执行器不是第二个人格中心。

## 交付清单

- [x] Codex：受约束的读取并行、独占屏障、顺序结算与取消收束；真实文件/SSE/SQLite 验证，并发验证不宣称固定加速倍率。
- [x] Pi：持久请求账本及原生委派汇总；重试、失败、取消、崩溃、缺失数据、去重和归属检查。
- [x] Pi：已声明范围内的工具/钩子兼容；版本、撤销、固定执行快照、结果与自定义记录的原子恢复；长名称及跨插件命名边界稳定路由。
- [x] DeepSeek Harness：组合插件、持久检查点和真实 WASM 程序化读取；内部调用沿用原准入与结算。
- [x] 开发工具：TS/JS/JSX 原生语言服务、进程树停止、实际打包资源与 Electron ASAR 归档执行。
- [x] Hermes：有来源的同人格会话检索；三轮自然语言自主选方法；独立结果验收；持久定时工作和取消。
- [x] 本地泛化与故障覆盖：陌生输入、跨目录、接口改变、撤销、重启、取消、错误恢复和来源撤回。
- [x] 后台 Live2D、身体连续性、根类型检查、lint、编译与已停止的测试垃圾清理；保留失败与复验记录。

## 统一约束

1. 完整提案先落盘，逐动作准入仍由当前生命状态、资源租约和风险策略决定。
2. 只有运行时明确允许且没有共享可变界面状态的只读动作可并行；修改、浏览器状态和桌面焦点保持独占。
3. 模型消息按提案顺序结算；取消必须停止并收束所有已启动的工作，不能留下后台执行。
4. 未报告的 token、费用和外部委派用量保持未知，不将动作上限冒充费用上限。
5. 扩展、PTC、语言服务和自动化使用同一责任树。崩溃后未知副作用先核对，不能盲目重放。
6. 长期泛化与主观生命感不能通过少量功能测试直接宣告完成。验收报告必须区分实现、自动测试与真实使用证据。
