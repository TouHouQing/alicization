# 文字、语音与角色表达交付闭环

目标：在 Phase 1 的同一人格、会话和消息内，让阅读保持真实流式，让语音自然分句，让口型、当前朗读位置和中断跟随实际播放；保留用户偏好的无声口型，不再用其速度拖慢正文。

## 职责与组件

- 文字呈现器：校验流包顺序、更新唯一消息、保留已显示正文；不等待语速计时器。
- 表达交付协调器：同一 turn/message 的阅读与发声状态、当前朗读范围、取消和跨窗口传播；不制造第二份回复。
- 语音规划与管线：同一已准入文本按语义短句合成；长内容、代码和结果使用可追溯的朗读范围；沿用免打扰策略和原语音能力。
- 音频播放器：报告实际开始、已播放时间、结束和失败；音频时钟驱动发声位置。
- 角色表达适配器：有声时用实际音频时间/对齐信息驱动口型；无声时使用独立的自然口型节奏；停止后不恢复过期队列。
- 聊天朗读提示组件：通过消息 ID 与只读交付状态显示正在朗读的位置和终态；普通 Markdown 内容保持原阅读和复制能力。

## 完成条件

- [x] 正文跟随已准入流包更新，不再被固定 230 ms/字节奏阻塞，仍只有一条回复。
- [x] 有声短聊按自然短句合成，声音未开始时不播放伪装成发声的口型。
- [x] 音频进度关联当前字词/语句，正文可提前显示；停顿、失败和暂停不持续推进口型。
- [x] 时间戳能力和估算降级明确，普通 TTS 不虚构精确音素对齐。
- [x] 长回答、代码和执行内容提供有限原文摘录及明确的完整朗读入口，摘录与原文一致。
- [x] 纯文字保留可配置的无声口型，阅读与角色表现分别完成和停止。
- [x] 新消息、停止、人格/会话切换、窗口关闭和陈旧事件统一取消相关工作。
- [x] 持久记录区分文字已显示、语音已播放和未说完，历史不会把未播放内容当成已听见。
- [x] 免打扰/主动提醒沿用既有策略，静音时不突然发声。
- [x] 定向单元与跨模块回归、类型检查、lint、编译通过；后台 Live2D 体验覆盖有声、无声、长内容、失败及打断。

## 验证原则

检查同一来源、同一消息、真实播放时钟和取消归属等跨模块不变量。真实产品验证使用后台测试窗口与合成身份，不影响用户主桌面；退出后导出必要证据并清理已确认归属的临时数据。语音硬件主观音色与服务商未提供的精确对齐能力单独说明，不能由静音测试代替。

## 实现记录

- 正文呈现按已准入数据块追加，保留顺序、重复包、取消和最终前缀校验；去除阅读对说话计时器的等待。
- 自动朗读从同一正文选取最多 160 个源字符，按自然短句进入原 TTS 管线；跳过代码块、URL，允许用户手动朗读完整正文（沿用 12,000 字符上限）。显式读代码保留运算符和变量名。
- 角色和字幕使用实际 AudioContext 进度；普通 TTS 使用基于语句读音和实际音频时长的估算。声学能量限制嘴部张开，停顿和中断不继续模拟发声。无声口型保持独立节奏，并保留跨流块的中文读音上下文。
- 交付状态绑定 card/session/turn/epoch，按修订号和已退役 epoch 拒绝旧事件。桌面聊天窗口与角色窗口通过独立 Eventa 通道同步状态和停止/完整朗读命令；独立字幕窗口接收实际播放字幕。
- 在第一个正文块之前绑定真正的 gateway attempt ID，避免提前发声与最终提交的 `:gwN` 后缀不一致，导致真实回执无法落库。
- 即使合成任务已经退出，`cancelIntent` 仍停止对应的活动音频和等待音频。产品验收同时检查停止耗时、真实声源结束和持久化的中断结果。
- 只在完整音频短句确实结束后确认源文字位置。`alignedTextEnd` 表示最后确认短句的源位置；摘录可以跳过代码等内容，不表示这个位置之前每个字符都已朗读。`excerpt-only` 记录正常结束的部分朗读，不能满足整段话或语音提醒的完整送达证明。
- `lastAudioReceipt` 与一般的 `lastReceipt` 同属原 expression owner；后来的正文呈现不会抹掉最近记录的音频结果。历史消息保存交付投影，单独恢复磁盘缓存不会重播声音。
