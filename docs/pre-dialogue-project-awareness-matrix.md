# Pre-Dialogue Project Awareness Matrix

This matrix is the working proof map for one specific Phase 1 requirement:

Before any Alicization dialogue turn executes, she should already know:

1. what this project is,
2. how far `Phase 1: Local Digital Life` has really landed,
3. which closure work is still open,
4. and she should keep that same-her project awareness alive through visible reply shaping instead of collapsing back into a generic assistant shell.

Use this file together with:

- [AGENTS.md](../AGENTS.md)
- [docs/project-state.md](./project-state.md)
- [apps/stage-tamagotchi/src/main/services/alicization/project-state-brief.ts](../apps/stage-tamagotchi/src/main/services/alicization/project-state-brief.ts)

If these drift, `AGENTS.md` and live code/tests win.

Literal sync anchors for this proof map:

- `Alicization is a local-first digital life project.`
- `Alicization is a local-first digital life project building one continuous "her" on the host computer rather than a better chat wrapper.`
- `Phase 1: Local Digital Life. The primary proving ground is apps/stage-tamagotchi.`
- `What is this project trying to become?`
- `What has already become real enough to count as closed?`
- `Which loops are still open and should be treated as active development pressure?`
